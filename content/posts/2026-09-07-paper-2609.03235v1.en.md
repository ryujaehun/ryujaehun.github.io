[Paper (arXiv v1)](https://arxiv.org/abs/2609.03235v1)

Compressing a long-context KV cache involves deciding **how much to keep for each head** and **which tokens to keep within that head**. SGD-KV scores heads with a task that asks the model to separate a set of documents and extract their keywords. The score determines each head's budget. Cumulative attention then determines which tokens fit inside that budget.

> On MRCR with a fine-tuned Qwen2.5-7B-Instruct-1M, SGD-KV scored 34.16 at 1M tokens with a 25% KV-cache budget. It scored above HeadKV (28.90) and DuoAttention (24.73) at the same budget and 9.13 points below FullKV (43.29). The 75% saving refers to the **KV-cache budget** in this comparison. See §4, Table 1.

## The new approach: SGD-KV

The KV cache holds keys and values from earlier tokens for reuse during decoding. With the model and batch size fixed, its size is proportional to the number of tokens stored. SGD-KV allocates more cache to heads that help combine information across a long input. The paper assigns each head a continuous importance score (§3.1–3.2, Appendix A.3).

### Computing the summarization score

The authors concatenate short documents from datasets such as CNN/DailyMail and DialogSum and record their original boundaries. They ask the model for the number of distinct chunks and the keywords for each chunk. For valid responses, they measure the attention from each generated keyword token to its matching input token within the corresponding chunk. When the same token appears more than once, they use its strongest attention link. See §3.1–3.2, Figure 1, and Equation 1.

$$
I_h = \frac{1}{c}\sum_{m=1}^{c}\frac{1}{\lvert K_m\rvert}
\sum_{j\in K_m}\max_n A_h(p_j^o, p_{j,n}^i)
$$

Here, $c$ is the number of chunks and $K_m$ is the keyword set for chunk $m$. The positions $p_j^o$ and $p_{j,n}^i$ identify the generated keyword token and a matching input token. The summarization score is $I_h$ averaged over valid samples.

### Allocating the KV-cache budget

The method reserves fixed budgets for initial sink tokens and a recent-token window. It divides the budget for the middle of the input in proportion to the normalized summarization scores. If a head receives more capacity than it can use, the surplus goes to heads with room left. Within each head, the method keeps tokens with the highest cumulative attention from the observation window, using an approach similar to SnapKV. See §3.3 and Appendix A.1.

In grouped-query attention (GQA), multiple query heads share a KV head, so the scores must be aggregated at the KV-head level. The paper's Qwen2.5-7B example has 28 query heads and 4 KV heads. Appendix A.7 compares maximum and mean aggregation within each group. It also evaluates variants that incorporate the summarization scores into token-attention aggregation.

## How it works: walking through a concrete example

Consider an illustrative input with a booking notice, a schedule change, and directions to a venue. If the model splits the input into chunks and produces the keywords “booking,” “change,” and “venue,” the diagnostic measures how strongly each head connects those generated tokens to the corresponding source chunks.

Suppose that the combined budget for the middle of the input is 4 tokens. The example allocation assigns 3 to head A and 1 to head B. If A's observation window gives the highest cumulative attention to the booking, change, and venue tokens, and B gives its highest score to the venue token, the retained entries look like this.

| KV head | Middle-token budget | Entries retained |
|---|---:|---|
| A | 3 | booking, change, venue |
| B | 1 | venue |

Both heads still keep the reserved initial and recent tokens. In this example, **the summarization score determines how many tokens to keep** and **cumulative attention determines which token positions to keep**.

## Results

### MRCR: compare at the same budget and context length

The table shows selected MRCR scores for the fine-tuned Qwen2.5-7B-Instruct-1M. SGD-KV, DuoAttention, and HeadKV use a 25% KV-cache budget. FullKV and MInference appear for reference (§4, Table 1, Appendix A.2).

| Method | 128K | 256K | 1M |
|---|---:|---:|---:|
| FullKV | 96.38 | 88.60 | 43.29 |
| MInference | 95.43 | 82.21 | 43.87 |
| DuoAttention | 89.82 | 73.78 | 24.73 |
| HeadKV | 74.81 | 66.98 | 28.90 |
| SGD-KV | 87.19 | 83.29 | 34.16 |

SGD-KV trails DuoAttention at 128K and overtakes it at 256K. At 1M it beats both eviction methods at the same budget, while FullKV and MInference still score higher. The ordering against HeadKV also changes with context length on Qwen3-32B. At 8K, SGD-KV scores 77.05 against HeadKV's 78.16. At 64K, the scores are 40.13 and 34.90 (§4, Table 1).

### ETHIC and BABILong: the gap to FullKV varies by task

- **ETHIC** — On Qwen3-32B, the SGD-KV average at a 25% budget is 28.38 and the FullKV average is 28.53. The corresponding Qwen2.5-7B-Instruct-1M scores are 21.34 and 21.65 (§4, Table 2).
- **BABILong** — At 1M tokens on the fine-tuned Qwen2.5-7B-Instruct-1M, SGD-KV scores 94.2, HeadKV at the same 25% budget scores 94.2, and FullKV scores 94.6. Table 4 averages QA1 through QA5 (Appendix A.5, Table 4).

### Using a summarization prompt when the real question is unavailable

Default token selection uses cumulative attention from the last 128 tokens, including the actual question. The paper compares **Query-Unaware**, which excludes the question, with **Proxy-Query**, which substitutes a fixed summarization prompt. On MRCR at 64K, SGD-KV scores 85.09 with the default window, 70.94 without the question, and 82.62 with the proxy. At 1M, the proxy scores 32.24 compared with 33.20 without the question. The effect varies with context length (§5, Tables 1 and 3).

### What changes when the allocation is reversed

In Appendix A.7, the authors report that reversing the allocation across heads used 3 times as much cache. On MRCR at 512K, standard SGD-KV scored 48.86 and the reversed allocation scored 8.61. At the same length, the Ipt., Max variant that uses summarization scores in token-attention aggregation scored 57.23. Table 5 reports this variant through 512K (Appendix A.7, Table 5).

## What to check before applying these results

The Qwen2.5-7B experiments use an additionally fine-tuned checkpoint. The original checkpoint and other models need their own comparisons. The 25% figure is a cache-budget ratio. Peak GPU memory and time to first token require separate measurements on the target model and serving setup (§4, Appendix A.2).

It also matters whether the real question is available when the cache is compressed. A proxy prompt is worth testing for a precompressed context that will be reused. Measure the proxy's effect and the quality gap to FullKV at the context lengths that the workload actually uses.

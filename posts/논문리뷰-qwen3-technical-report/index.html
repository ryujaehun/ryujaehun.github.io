논문 링크

Qwen 3: 생각량을 조절하는 거대 MoE 언어모델의 진화

한 줄 요약 (TL;DR)

Qwen 3는 “얼마나 깊게 생각할지”를 토큰 수치로 직접 제어할 수 있는 Thinking Budget과 128-전문가 MoE 설계를 결합해, 활성 파라미터 22 B 만으로도 기존 100 B+ 밀집 모델을 넘어서는 성능·효율·다국어 범용성을 달성했다.

핵심 아이디어

  1. Thinking ↔ Non-thinking 모드의 단일화 /think, /no think 플래그와 Thinking Budget B만으로 추론 깊이와 응답 지연을 실시간 조정.

  2. 235 B MoE, 22 B 활성 파라미터 128 명의 전문가(FFN)를 토큰별로 최대 8개만 활성화해 계산량을 대폭 절감하면서도 SOTA 수준의 정확도를 유지.

  3. 36 T 토큰·119개 언어 학습 + 단계별 증류 거대 데이터·다국어·코드·수학을 두텁게 학습한 뒤, 대형 모델의 지식을 0.6 B~14 B 경량 모델에 전파해 엣지까지 스펙트럼을 확장.

배경: 그들이 해결한 문제

  • 성능 격차: GPT-4o, Claude 3 등에 비해 오픈 가중치 모델의 벤치마크 점수는 여전히 5–15 pt 낮았다.
  • 추론 비용: 100 B 이상 밀집 모델은 배포·서빙 비용이 비현실적.
  • 모드 이원화: 복잡한 Chain-of-Thought(Cot) 모델과 빠른 채팅 모델을 별도로 운영해야 하는 비효율 존재.
  • 장문·다국어 취약: 4k-8k 토큰 한계와 영어 중심 학습 데이터로 글로벌 사용성에 제약.

작동 원리: 구체적인 예시로 살펴보기

입력 User: "2 + 3는 얼마야?" /think (B = 4)

Step-by-Step

  1. 토크나이즈: 프롬프트 + 플래그 → 토큰 시퀀스.
  2. 라우팅: 각 토큰 은닉 상태를 128개 전문가 중 Top-8로 분배.
  3. 이유(Thinking) 생성: <think> 블록에 “2와 3을 더하면 5” 등 내부 추론을 쌓고 N < 4까지 계속.
  4. 게이트 종료: N = 4 도달 → <stop-thinking> 삽입.
  5. 답변 출력: <think>…</think> 5. 비추론 모드면 빈 <think></think>만 남는다.

이 간단한 카운터 하나가 추론 깊이(품질) ↔ 응답 시간(비용) 사이의 실시간 균형점을 만들어 낸다.

우리의 관점: 강점, 한계, 그리고 이 연구가 중요한 이유

💪 강점

  1. 성능-효율 동시 달성: 22 B 활성 파라미터로 100 B+ 밀집 모델을 넘어서는 첫 사례 중 하나.
  2. 모드 통합의 실용성: 하나의 체크포인트로 CoT·채팅을 오가는 간결한 운영.
  3. 광범위 모델 스펙트럼: 0.6 B–235 B까지 동일 레시피로 품질 일관성 확보.

⚠️ 한계

  • RULER 같은 검색-중심 과제에서 Thinking 모드가 성능을 깎아먹는 현상.
  • 128-전문가 분산 인프라는 운영 난도가 높고 지연 편차 위험이 있다.
  • 36 T 크롤링 데이터의 라이선스·프라이버시 컴플라이언스가 상세히 공개되지 않았다.

🌟 왜 중요한가?

Qwen 3는 추론 깊이의 토큰-단위 제어라는 새로운 사용자 패러다임을 실증했다. 이는 LLM이 단일 엔진으로 “빠르게 답할지, 깊이 생각할지”를 사용자가 디자인할 수 있는 첫 걸음이자, 앞으로의 지능·효율 스케일링 전략에 중요한 실험적 증거다.

다음 단계는?: 앞으로의 길

  1. Auto-Budget 스케줄러 문제 난이도를 예측해 B를 자동 튜닝, 품질·지연을 최적화.
  2. Retrieval-Aware 모드 전환 검색 쿼리 감지 시 자동으로 /no think 전환해 장문-검색 취약점 완화.
  3. 친환경 MoE 인프라 온디맨드 Expert Pruning, 캐시 재활용 등으로 에너지·지연 편차를 최소화.
  4. 데이터 거버넌스 투명화 36 T 코퍼스 필터링·라이선스 검증 파이프라인을 공개해 커뮤니티 감사 촉진.
  5. 멀티모달-Tool 통합 Vision/Audio 토큰까지 Thinking Budget 체계로 관리, 에이전트 작업 범위를 확장.

결론: Qwen 3는 “토큰으로 생각량을 조절한다”는 발상과 MoE 효율을 결합해 오픈소스 LLM의 지형을 한층 넓혔다. 남은 과제—컨텍스트 확장, 자동 버짓, 컴플라이언스—를 해결한다면, 이 접근법은 차세대 범용 AI 엔진의 유력한 로드맵이 될 것이다.

비밀 병기: 토큰-기반 Thinking Budget 게이팅

공식/알고리즘 한눈에 보기

  1. 사용자가 thinking budget $B$ (예: 8192 tokens)을 지정한다.
  2. 모델은 내부 토큰 <|think|> 로 체인-오브-쏘트(CoT) 구간을 시작한다.
  3. 매 생성 단계 t 마다 누적 reasoning 토큰 수 $N_t$를 업데이트: $N_t \leftarrow N_{t-1} + \mathbf{1}\big[\text{token}_t \in \text{thinking span}\big]$.
  4. 종료 조건: $N_t \ge B$ 이면 즉시 <|answer|> 토큰을 내보내 reasoning 모드를 종료하고, 최종 답변 구간으로 전환한다.
  5. 이 하드 게이팅은 디코더-루프 안에서 O(1) 연산으로 동작하므로 추론 지연(latency)에 거의 오버헤드를 추가하지 않는다.

어떤 기능을 수행하나?

  • 계산-예산 직관적인 제어 사용자는 한 줄 파라미터 $B$ 로 “얼마나 깊게 생각할지”를 직접 구체화할 수 있다. 긴 문제에는 큰 $B$, 채팅형 응답에는 작은 $B$를 주면 된다.
  • 모드 통합 같은 가중치 안에 thinking·non-thinking 두 모드를 넣어두고, 이 게이트 하나로 스위칭한다. 별도 모델을 불러올 필요가 없어 메모리와 시스템 복잡도가 크게 줄었다.
  • 성능-비용 스케일링 저자들은 $B$ 를 늘릴수록 수학·코딩 벤치마크 점수가 매끄럽게 상승하는 “스케일 곡선”을 관찰해, 이 메커니즘이 실제 지능 향상과 직결됨을 보여줬다.

왜 이 한 가지가 방법론의 ‘필수 부품’인가?

  1. 추론 효율성과 품질의 균형점 장황한 CoT를 자동으로 잘라낸다는 점이 핵심이다. Thinking 모드를 무제한으로 켜두면 불필요한 토큰이 폭증해 지연·비용이 급등한다. Budget gate 없이는 두 모드를 하나의 모델에 묶는 전략이 현실적으로 불가능하다.
  2. 사용자 경험의 가변성 제거 동일한 질문에서도 예산이 같으면 출력 길이·응답 시간이 일관되게 유지된다. 이는 프로덕션 서비스에서 SLO(Service-Level Objective)를 맞추는 데 결정적이다.
  3. 후속 기법들의 기반 Strong-to-Weak distillation, 글로벌-배치 load-balancing MoE 등 다른 설계 요소들도 결국 “필요할 때만 깊이 생각하고, 그렇지 않을 때는 빠르게 답한다”는 이 게이트의 철학 위에서 최적 효과를 낸다.

요컨대, Thinking Budget 게이팅은 Qwen3의 모든 혁신을 가능하게 만든 스위치다. 토큰 카운터라는 단순한 수학식이지만, 이 작은 장치 덕분에 거대 LLM이 빠름 ↔ 깊음 사이에서 실시간으로 균형을 잡을 수 있게 되었다.

1. 어텐션 스택의 기본 골격

  • Transformer Decoder-only 구조를 채택해 입력과 출력을 한 시퀀스 안에서 처리합니다. 인코더-디코더 쌍이 따로 존재하지 않으므로 별도의 상호작용 단계는 없습니다.
  • 모든 변형에서 Grouped Query Attention (GQA) 를 사용합니다. 즉, Query-헤드는 많지만 Key/Value-헤드는 그보다 적어 메모리와 연산을 아낍니다.

3. 위치 인코딩(Positional Encoding)

  • 전 모델이 RoPE(Rotary Positional Embedding) 을 사용해 각 토큰의 위치 정보를 각도 회전에 매핑합니다. RoPE는 컨텍스트 길이를 쉽게 확장할 수 있어 Qwen3가 최대 128 K 토큰까지 다룰 수 있는 핵심 요소입니다.
  • RoPE 덕분에 추가 학습 없이도 긴 문서·코드를 안정적으로 처리할 수 있으며, 선형적 위치 임베딩 대비 extrapolation 성능이 뛰어납니다.

4. 학습 안정화와 추가 모듈

  • RMSNorm(Pre-Norm) 으로 깊은 레이어에서도 그래디언트 흐름을 완화합니다.
  • QK-Norm(Attention에만 적용)으로 스케일이 큰 Query 값을 정규화해 큰 모델에서도 학습이 흔들리지 않습니다.
  • FFN은 SwiGLU 활성화를 사용해 파라미터 효율 대비 표현력을 높입니다.

5. Seq2Seq 모델이 아닌 이유

Qwen3는 GPT-류와 같은 단일 디코더 언어 모델이므로, 고전적인 Seq2Seq(인코더가 입력 요약 → 디코더가 출력 생성) 단계가 없습니다. 따라서 “인코더-디코더 상호작용”이 아니라 자기-회귀(decoder-only) 어텐션 한 스택이 모든 역할을 수행합니다.

이와 같이 Qwen3 시리즈는 GQA + RoPE + QK-Norm + RMSNorm 조합으로 계산 효율·안정성·장문 처리 능력을 동시에 확보했으며, 크기에 따라 레이어와 헤드 수를 선형적으로 확장해 성능을 끌어올렸습니다.

학습 목표 (Objective)

  • Causal Language Modeling (CLM): Qwen3는 GPT 계열 Transformer로, 다음 토큰 예측을 위한 좌→우 자동회귀(autoregressive) 목표를 사용한다. 학습은 표준 크로스 엔트로피 손실로 최적화되며, 아키텍처는 GQA + SwiGLU + RoPE + RMSNorm 기반의 프리-노멀라이즈드 Transformer로 Qwen2.5 계열과 동일한 설계를 따른다.

파인튜닝 & 포스트-트레이닝 전략

1️⃣ 네 단계(post-training) 파이프라인

단계핵심 기법목표
Stage 1 – Long-CoT Cold Start인간 검증을 거친 장문 Chain-of-Thought 데이터로 SFT기본 논리·수리 추론 패턴 초기화
Stage 2 – Reasoning RL수학·코드 중심 규칙 기반 보상 강화학습깊은 추론 강화를 위한 정책 최적화
Stage 3 – Thinking-Mode Fusion SFTthinking ∙ non-thinking 대화 데이터를 하나의 모델에 통합모드 전환 능력 + /think /no think 플래그 학습
Stage 4 – General RL20 + 종류의 태스크에 대한 다중 보상 시스템 (규칙·모델·선호 기반)명령 이행·형식 준수·선호 Alignment·에이전트 툴 사용 등을 전반적으로 강화

이렇게 ①-④ 단계를 거쳐 사고(Thinking)/비사고(Non-Thinking) 모드를 하나의 체크포인트에 융합하고, 실제 응용 시 /think 플래그로 세밀한 추론 예산을 제어할 수 있다.

2️⃣ Strong-to-Weak Distillation (경량 모델용)

  • 235 B/32 B 등 대형 교사(teacher) 모델의 logit 지식을 0.6 B–8 B 학생 모델에 증류.
  • 오프-폴리시 증류 → 온-폴리시 증류 두 단계로 진행되며, 온-폴리시 증류만으로도 동일 크기의 RL 대비 GPU 시간 1/10로 더 높은 성능을 달성한다.

정리

  • 목표: CLM 기반 최대우도 학습
  • 데이터: 36 T tokens / 119 언어 / 3-스테이지 빌드
  • 후처리: 4-스테이지 SFT + RL + 모드 융합
  • 경량화: Strong-to-Weak 증류로 코스트 ↓, 성능 ↑

이러한 체계적인 학습·최적화 설계가 Qwen3 패밀리(0.6 B ~ 235 B)를 일관된 품질과 효율로 확보하게 만든 핵심이다.

논문 링크

Kimi K2: 오픈소스 LLM이 에이전트 지능을 향해 내딛은 한 걸음

TL;DR

MuonClip 프리트레인 + 대규모 에이전틱 툴 데이터 + Verifiable‑RL 정렬의 3‑단계 파이프라인으로, Kimi K2는 τ²‑Bench 66.1·SWE‑bench 65.8 등에서 기존 오픈소스 모델을 두 자릿수 p 이상 능가하며 GPT‑4급 장기 추론·툴 사용 성능에 근접했다.

핵심 아이디어

  1. 안정성 ― QK‑Clip 으로 Muon 옵티마이저의 로짓 폭주를 선제 차단
  2. 데이터 ― 20 K 툴·수천 에이전트·다중 루브릭 과제를 자동 합성해 에이전틱 행동 궤적을 대량 확보
  3. 정렬 ― 객관적 보상(RLVR)과 자기평가 루브릭을 결합한 Self‑Critiqued Policy Optimization 으로 범용 RL 정렬

배경: 그들이 해결한 문제

대부분의 공개 LLM은 “정적 모방 학습 → 단일 턴 생성”에 머물러 툴 사용·장기 계획·다중 턴 추론 능력이 미흡했다. 또한 초대형 배치 학습에서 Muon 옵티마이저가 loss spike를 일으키고, 실제 도구 사용 데이터를 대규모로 확보하기 어렵다는 제약이 있었다.

MuonClip — ‘비밀 병기’

$$ \gamma_h=\min\!\Bigl(1,\;\frac{\tau}{S_{\max}^{\,h}}\Bigr),\quad S_{\max}^{\,h}=\tfrac1{\sqrt d}\max_{i,j}(q_i^{\,h}\cdot k_j^{\,h}) $$

헤드 h의 최대 로짓이 임계값 τ를 넘으면 W_q,W_k를 √γ_h 배로 축소한다. 덕분에 15.5 T 토큰을 단 한 번의 loss spike 없이 학습하며 토큰 효율을 극대화했다.

우리의 관점: 강점, 한계, 그리고 이 연구가 중요한 이유

강점

  • 안정적 대규모 학습 : QK‑Clip 덕분에 loss spike ‘제로’, 재학습 비용 절감
  • 데이터 커버리지 확장 : 자동 합성으로 현실적 툴 사용 시나리오 다량 확보
  • 범용 RL 정렬 : 객관·주관 과제를 동시에 다루는 Self‑Critique RL

한계

  • 지식 회수 & 전문 과학 QA : GPT‑4.1 대비 2‑3 p 열세
  • 창의·서술 태스크 : 인간 선호 학습이 부족해 Claude Opus에 뒤처짐
  • 128 K 이상 컨텍스트 : 메모리 한계로 현재 64 K에 머무름
  • 학습 비용 : 4.2 M GPU‑hours — 재현 장벽이 높다

중요성

Kimi K2는 오픈소스 LLM이 에이전트형 지능을 실질적으로 추구할 수 있음을 증명했다. 이는 연구·산업계 모두에게 “폐쇄형 독주를 깨뜨릴 수 있다”는 신호탄이다.

다음 단계는?: 앞으로의 길

  1. Adaptive QK‑Clip — 배치·도메인별 임계값 자동 튜닝
  2. 실사용 로그 통합 — 합성 데이터 편향 완화
  3. 다목적 보상 혼합 — 정확성·창의성·안전성을 동시에 최적화하는 RL
  4. 128 K+ 컨텍스트 최적화 — Flash‑Attention v3, 압축 어텐션 도입
  5. Agentic Firewall — 다중 툴 호출 능력의 악용을 방지하는 권한 관리

마무리 한마디 Kimi K2는 “안정성·데이터·정렬” 세 축을 통합해 오픈 모델이 에이전트 지능으로 도약할 수 있음을 보여줬다. 남은 과제는 편향, 창의성, 효율성 — 바로 다음 혁신의 무대다.

1. 연구 공백 및 미해결 질문

Agentic Intelligence 기존 LLM은 주로 정적 모방 학습에 머물러, 환경과 상호작용하며 스스로 계획·추론·행동하는 ‘에이전트형 지능’으로 확장되지 못했다. 저자들은

  • 제한적인 고품질 데이터 속에서 일반 지식을 학습하면서도
  • 멀티‑스텝 추론·장기 계획·툴 사용과 같은 고차 능력을 부여할 효율적 토큰 활용(Token Efficiency) 과
  • 고품질·대규모 에이전트 행동 궤적을 생성·활용할 방법 이 결여돼 있다고 지적한다.

2. 기존 연구의 결정적 한계

  1. Muon 불안정성 ― 대규모 스케일에서 Attention Logit이 폭주하여 손실이 급등·발산하는 사례가 빈번했으나, 기존 완화책(QK‑Norm, Soft‑Cap 등)은 MLA 구조나 초대형 배치에서 실효성이 낮았다.
  2. 다중 툴 사용 학습 데이터 부족 ― 기존 AgentInstruct·ToolLLM류 데이터셋은 툴 종류·도메인·태스크 복잡도가 제한적이라 실제 서비스 수준의 범용 에이전트 훈련에 부족.
  3. RL 보상 편협성 ― 승패가 명확한 문제(코딩·수학) 위주로 설계되어, 상대적 선호·안전성·창의성 등 주관적 요인을 정밀하게 반영하지 못함.

1. 안정적 · 효율적 프리트레이닝MuonClip(Muon + QK‑Clip)으로 15.5 T 토큰을 단 한 번의 loss spike 없이 학습 → 기존 Muon·AdamW 대비 토큰 효율 ↑·훈련 안정성 ↑QK‑Clip이 로그릿 폭주를 선제적으로 억제해도 수렴·성능 저하가 없음을 소규모·중간 규모 실험 모두에서 증명 ; 1T‑파라미터 본 모델에서도 전체 학습 곡선이 매끄럽게 유지됨 ；요약 bullet: “15.5 T tokens without a single loss spike”
2. 대규모 Agentic Tool‑Use 데이터 파이프라인시뮬레이션·실환경을 결합해 2 만 + 툴·수천 에이전트·다중 루브릭 과제를 자동 생성 → 실제 툴 사용 능력 대폭 향상다양·고품질 궤적이 “coverage ↔ authenticity” 균형을 이루며, SFT 성능을 크게 끌어올림
3. 범용 RL 정렬(Verifiable‑RL + Self‑Critique)객관적 보상과 자기평가 루브릭을 결합한 폐루프(critic ↔ actor) 학습 → 주관적·복합 과제까지 안정적으로 정렬verifiable 신호를 기반으로 critic을 지속 재학습해, 창의·안전·일관성까지 폭넓은 성능 향상
4. 실측 벤치마크 우위τ²‑Bench(툴 사용) 66.1, ACEBench 76.5, SWE‑bench 65.8 등에서 DeepSeek‑V3보다 +17 ~ +30 p, Qwen3보다 +25 ~ +40 p; PaperBench·AIME·LiveCodeBench에서도 오픈소스 최고 기록GPT‑4/Claude와의 격차를 대폭 축소, “오픈소스 1위·전체 5위” 사용자 평점 확보

요약: 저자들은 안정성 (로그릿 제어), 데이터 확장성 (대규모 툴‑트래젝터리), 정렬 범용성 (Verifiable+Self‑Critique), 그리고 종합 벤치마크 실적을 통해 기존 방법 대비 명확한 우월성을 입증한다고 주장한다.

Kimi K2 핵심 방법론 Step‑by‑Step 가이드

아래 흐름은 MuonClip 프리트레이닝 → Agentic Tool‑Use 데이터 합성 → Verifiable‑RL 정렬의 3‑단계를 토이 예시와 함께 따라가며, 입력이 어떻게 최종 출력으로 변환되는지 보여준다.

1. MuonClip : 폭주 없는 토큰‑효율 프리트레이닝

1‑A 알고리즘 단계

단계연산설명
①Muon update모멘텀 M_t, 뉴턴‑슐츠 근사 O_t 로 RMS‑Norm 스케일을 맞춘 뒤 가중치 W_t 갱신
②QK‑Clip 검사각 어텐션 헤드 h 에 대해 S_max^h(최대 로짓) > τ 인지 확인
③가중치 리스케일폭주 헤드만 γ_h = τ / S_max^h 로 W_q, W_k 를 재스케일 → 로짓 폭주 차단, 학습 신호는 그대로 유지
④자동 비활성화충분히 안정화되면 QK‑Clip trigger 빈도가 0%로 수렴해 완전히 꺼짐
$$ \textstyle S_{\max}^h=\frac1{\sqrt d}\max_{i,j}(q_i^h\cdot k_j^h),\; \gamma_h=\min\bigl(1,\tfrac{\tau}{S_{\max}^h}\bigr) $$

3. Verifiable‑RL + Self‑Critique 정렬

3‑A 학습 루프

  1. Actor Rollout : 정책 π_old 가 K 개의 답안 {y₁…y_K} 생성
  2. Critic 평가 : Verifiable 보상 (r) + Self‑Critique Rubric 로 랭킹 / 점수 계산
  3. 정책 업데이트
$$ \small L_{\text{RL}}(θ)=\mathbb{E}_{x\sim\mathcal{D}}\Bigl[\frac1K\sum_{i=1}^{K}\bigl(r(x,y_i)-\bar r(x)-τ\log\tfrac{π_θ(y_i|x)}{π_{\text{old}}(y_i|x)}\bigr)^2\Bigr] $$
  1. Critic 재훈련 : verifiable signal 로 지속 교정 → 폐루프 정렬
  2. Self‑Critique 확장 : 주관적 분야(창의·안전성 등)도 보상 학습

📌 정리

  • MuonClip 은 $15.5 \text{T}$ 토큰 프리트레인을 단 한 번의 loss spike 없이 완주하게 해 토큰 효율·안정성을 동시에 확보했다.
  • Agentic 데이터 파이프라인 이 2 만 + 툴·수천 에이전트 궤적을 합성해 툴 사용 능력을 비약적으로 끌어올렸다.
  • Verifiable‑RL + Self‑Critique 가 주관·객관 태스크 전반을 아우르는 범용 정렬을 달성했다.

🧨 ‘비밀 병기’ — QK‑Clip 스케일링

$$ \boxed{ \gamma_h=\min\!\Bigl(1,\; \tfrac{\tau}{S_{\max}^{\,h}}\Bigr)},\quad S_{\max}^{\,h}=\frac{1}{\sqrt{d}}\max_{i,j}\bigl(q_i^{\,h}\cdot k_j^{\,h}\bigr) $$
요소설명
$S_{\max}^{\,h}$헤드 $h$에서 관측된 최대 어텐션 로짓(scaled dot‑product)
$\tau$허용 가능한 로짓 상한(실험값 ≈ 100)
$\gamma_h$폭주 시 $(0,1)$로 W_q, W_k 재스케일 계수

⚙️ 어떻게 작동하나?

  1. 모델이 한 배치에서 계산한 어텐션 로짓 값 $S_{\max}^{\,h}$ 를 실시간으로 추적

  2. 로짓이 임계값 $\tau$ 를 넘는 헤드에 한해

    $$ W_q^{\,h}\leftarrow\sqrt{\gamma_h}\,W_q^{\,h},\; W_k^{\,h}\leftarrow\sqrt{\gamma_h}\,W_k^{\,h} $$

    로 즉시 축소(클리핑)

  3. 이후 학습이 안정되면 $S_{\max}^{\,h}\le\tau$가 유지돼 자동으로 비활성화되어 성능 손실이 없다.

🚀 왜 필수적인가?

  • 로짓 폭주 방지 → 학습 안정성 Muon류 옵티마이저가 초대형 배치·장훈련에서 보이던 loss spike를 제로(0)로 만들었다.
  • 토큰 효율 극대화 동일한 15.5 T 토큰으로도 재시작·재학습 없이 끝까지 수렴 → 비용·시간 절감.
  • 후속 단계 모두의 전제조건 안정적 프리트레인이 없으면 대규모 에이전틱 데이터 학습·RL 정렬도 무의미해진다. QK‑Clip이야말로 Kimi K2 전체 파이프라인을 성립시킨 결정적 단일 구성요소다.

2. 저자가 언급하지 않은 잠재적 한계 (추정)

2‑1 모델·알고리즘 관점

  1. QK‑Clip의 하이퍼파라미터 민감성   - 임계값 τ 선정이 데이터 도메인·배치 크기에 따라 최적값이 달라질 수 있음.   - τ 부적합 시 under‑clipping → loss spike 재현 / over‑clipping → 표현력 저하.

  2. Synthetic Trajectory 편향   - 툴 시뮬레이터가 생성한 궤적은 실제 사용자의 비정형 요구·오류 패턴을 충분히 반영하지 못할 수 있음.   - 실제 서비스 투입 시 “훈련 중 본 적 없는 툴 상호작용” 에 취약 가능성.

  3. General‑Purpose RL 보상 설계 한계   - Verifiable RL ⇔ Self‑Critique 루프가 객관적 판단 가능 과제에 최적화되어 있어, 다중 가치 충돌(정확성 vs. 창의성 vs. 안전성) 상황에서 보상 신호가 모호해질 여지.

2‑2 시스템·운영 관점

  1. 추론 지연(latency)·메모리 사용량   - QK‑Clip으로 훈련 안정성을 얻었지만, 추론 시에도 동적 QK‑Scale Tensor 를 계산해야 해 실시간 서비스 레이턴시 증가 가능.

  2. 확장성 / 탄소 발자국   - 1 T 파라미터 모델을 다중 GPU로 배치하면 에너지 소비·냉각 비용이 급증 → 친환경·경제성 이슈.

  3. 보안·툴 오용   - 다중 툴 호출 능력이 강화된 만큼, 악의적 사용자가 API 키 누수·권한 상승 공격을 자동화할 위험.

2‑3 사회·윤리 관점

  1. 편향 전이   - 자체 합성 데이터가 독자적 편향을 가질 경우, RL 정렬 단계에서 “편향된 보상” 이 강화될 가능성.
  2. 고용·산업 영향   - SWE‑bench 수준의 자동 패치 능력은 저숙련 백엔드 유지보수 직무를 대체할 우려가 있음.

3. 요약 & 시사점

  • 저자 인정 한계: 지식 회수·전문 QA·창의 태스크·장컨텍스트·훈련 비용.
  • 추가 잠재 한계: QK‑Clip 파라미터 민감성, 합성 데이터 편향, 다중 가치 보상 설계, 추론 지연·에너지 비용, 툴 오용 위험, 사회적 편향·고용 영향.
  • 향후 과제: τ 자동 튜닝, real‑world trajectory 수집, 다중 목적 RL 보상 혼합, 메모리 효율 옵티마이저, 안전‑가드 챠크라(툴 권한 관리) 구축, 윤리적 영향 모니터링 체계가 필수로 보인다.

2. 논문의 한계에 기반한 추가·대안적 연구 궤적

아래 항목들은 논문에서 직접 언급되지 않았으나, 한계 분석(§ 1.5.1)과 최신 트렌드를 토대로 도출한 논리적 다음 단계 제안이다.

2‑A 알고리즘·모델 측면

  1. Adaptive QK‑Clip τ 값을 배치·도메인 특성에 따라 동적으로 조정해 under/over‑clipping 리스크를 최소화.
  2. 실사용자 툴 로그 수집 합성 궤적의 편향을 보완하기 위해 실제 서비스 로그를 익명화·샘플링하여 SFT/RL에 통합.
  3. 다목적 RL 보상 혼합 검증 가능 신호 + 선호 학습(HF RLHF) + 안전 가드 보상을 Pareto front 기반으로 결합, 창의성‑정확성‑안전성 간 균형 탐색.
  4. 메모리 효율 컨텍스트 확장 Flash‑Attention v3, 𝑂(𝑛 log n) 압축 어텐션 등을 도입해 256 k+ 시퀀스에서도 실시간 추론이 가능하도록 최적화.

2‑B 시스템·운영 측면

  1. 그린 AI 학습 레시피 전력‑탄소 모니터링을 통해 GPU utilization ↔ 에너지 효율 최적 스케줄링 연구.
  2. 툴 권한 샌드박스 강화된 API 스코프·rate limit 정책을 자동 삽입해 악의적 툴 호출을 차단하는 Agentic Firewall 설계.
  3. 모듈형 페일오버 RL rollout 중단점 저장·재개 기능을 표준화해 대규모 클러스터 장애 시 학습 손실을 최소화.

2‑C 사회·윤리 측면

  1. 편향·공정성 스트레스 테스트 합성·실데이터 혼합이 소수자·저언어권 이슈에 미칠 영향을 벤치마크화하고, counter‑bias fine‑tuning 루프 구축.
  2. 직무 영향 분석 SWE‑bench 급 자동 패치 기능이 개발자 생태계에 미칠 경제적 파급을 계량화, 보완 교육·전환 프로그램과 연계.

🗂️ 토큰화 전략

항목세부 내용
방식Tiktoken BPE(Byte‑Pair Encoding) 기반 자체 토크나이저 TikTokenTokenizer 사용 (Hugging Face )
어휘 파일tiktoken.model (BPE merge‑ranks) 로드 → 어휘 크기 n_vocab 계산 (Hugging Face )
프리‑토크나이저 규칙pat_str 정규식으로 한·영·숫자·공백·구두점 패턴을 구분하여 미세 분절 (Hugging Face )
특수 토큰BOS [BOS], EOS [EOS] 및 시스템 프롬프트용 `<im_user>` 등 256 개 예약 토큰 사전 할당 (Hugging Face )

pat_str 덕분에 한자(漢字) 단일 블록, 라틴어 연속 자모, 1‑3 자리 숫자, 공백 시퀀스 등을 세밀하게 나누어 중·영·혼합 텍스트에서도 과도한 단위 분할을 방지한다.

🚧 OOV(어휘 외) 처리

단계동작
1입력 토큰이 encoder 사전에 없으면 _convert_token_to_id 가 unk_id(기본값 `"<reserved_special_token_249>"`) 를 반환 (Hugging Face )
2실제로는 byte‑level BPE 특성상 임의 문자열도 하위 바이트 조각으로 분해되므로 OOV 발생 확률이 극히 낮다.
3디코딩 시 unk_id 는 <unk> 문자열이 아닌 예약 특수 토큰 표시로 복원되어 정보 손실을 최소화한다.

🧹 텍스트 정제·정규화 파이프라인

  1. 입력 전처리 pre_tokenizer_process → 현재는 원본 문자열을 그대로 반환(추가 클린업 없음) but pat_str 단계에서 공백·줄바꿈·구두점을 별도 토큰으로 분리해 노이즈를 구조화.
  2. 대용량 문자열 분할 encode 내부에서 최대 400 k 문자 제한을 초과하면 연속 공백 vs 비공백 25 k 단위로 슬라이스 ➜ _split_whitespaces_or_nonwhitespaces 루틴으로 메모리 폭주 방지 (Hugging Face )
  3. 바이트 정규화 bytes_to_unicode() 매핑으로 UTF‑8 바이트 ↔ Unicode 안정적으로 변환 ➜ 제어 문자·이모지 등 특수 바이트 시퀀스도 안전하게 인코딩.
  4. 대소문자·구두점 보존 별도 lower‑casing·stemming 불필요 → 모델이 원형 토큰에서 직접 대소문자·기호 패턴 학습.
⏩ 핵심 요약
  • TikToken BPE + 한·영 혼합 Regex 분절 → 다국어·코드·숫자에 모두 강인한 토큰화.
  • 256 개 예약 특수 토큰으로 시스템 메시지·역할 구분·패딩 등을 일관되게 처리.
  • OOV 는 byte‑level 분해로 사실상 소거; 극단적 예외는 unk_id 로 포획.
  • 정규화 는 “과도한 클렌징보다 원형 유지” 전략: 공백·줄바꿈·바이트 레벨만 안전 처리해 정보 보존과 학습 효율을 동시에 노린다.

모델 아키텍처 개요

구성 요소Kimi K2 값
트랜스포머 층 수61 decoder‑only 블록
어텐션 헤드 수64 (DeepSeek‑V3의 128 → 64로 절반 감축)
히든 차원7 168 (모델) / 2 048 (각 MoE expert)
MoE 전문가총 384, 토큰당 8 active → sparsity 48 (384 ÷ 8)

요약 : Kimi K2는 1.04 T 파라미터의 MoE 트랜스포머로, 32 B 파라미터만 활성화된다. 계산 비용을 줄이기 위해 헤드를 64개로 축소하고, 층 수는 유지했다. 

어텐션 메커니즘 구성 ― Multi‑head Latent Attention (MLA)
  flowchart TD
    subgraph 한 층의 MLA
        QK_proj[Query / Key 투영]<-- MoE Expert 선택 -->Switch
        Switch-->Heads64[64 어텐션 헤드]
        Heads64-->LatentMemory[Latent Memory 공유 키 k_R]
        Heads64-->HeadSpecific[헤드 전용 q_C, k_C, q_R]
    end
  • 공유 (latent) 키 k_R와 헤드 전용 컴포넌트(q_C, k_C, q_R)를 분리하여 장기 컨텍스트를 효율적으로 재사용한다.
  • MLA에 특화된 QK‑Clip 로짓 크기 제어는 헤드별로 q_C, k_C, q_R에만 적용되고, 공유 k_R은 건드리지 않는다.
위치 인코딩 전략

  • MLA는 RoPE(Rotary Position Embedding) 변형을 사용한다.

    • 헤드 전용 회전(q_R)과 공유 회전(k_R)으로 분리하여, 각 헤드가 위치 정보에 대해 독립적인 표현력을 가진다.
    • RoPE는 $\sin$⁄$\cos$ 회전을 통해 위치 관계를 곱셈적(상대적)으로 부호화하므로, 128 K 토큰까지 스케일할 때도 메모리 추가 없이 거리 정보를 보존한다.
$$ \newcommand{\textsc}[1]{\text{\small\textsf{#1}}} \underbrace{R_\theta}_{\textsc{rotary}}\,Q = \begin{bmatrix} \cos\theta & -\sin\theta\\ \sin\theta & \phantom{-}\cos\theta \end{bmatrix} Q $$
(참고) Seq2Seq 여부

Kimi K2는 순수 decoder‑only 구조이며 별도의 인코더·디코더 상호작용은 존재하지 않는다. 따라서 입력 컨텍스트와 출력이 동일 스택을 통해 처리된다.

핵심 포인트 정리
  1. 61‑층 / 64‑헤드 MLA 트랜스포머
  2. RoPE 기반 이중(공유·헤드 전용) 위치 인코딩으로 긴 문맥 안정화
  3. 384‑expert MoE와 sparsity 48로 계산량 ↘, 표현력 ↗

이러한 설계는 128 K 문맥과 agentic tool‑use 같은 장기 추론 시나리오에서 높은 효율·성능을 동시에 달성하는 데 핵심 역할을 한다.

학습 목표 (Objective)

Causal Language Modeling (CLM) – 모델은 다음 토큰 예측을 통해 파라미터를 학습하는 전형적인 디코더‑only / autoregressive 설정을 따른다. 논문 곳곳에서 “chunk‑wise autoregressive generation”이 전제가 되어 있음을 확인할 수 있다. 이후에는 Supervised Fine‑Tuning (SFT) → Reinforcement Learning 단계로 이어져, CLM 목표 위에 다양한 보상 신호를 추가로 최적화한다.

프리트레이닝 코퍼스

규모소스/도메인특징
15.5 조(high‑quality) 토큰웹 지식, 코딩 PR/이슈, 수학·과학 문서 등 다중 도메인초거대 MoE Transformer(활성 32 B 파라미터)로 학습
합성(synthetic) 데이터지식·수학 영역별 재표현(rephrasing) 파이프라인토큰 효율(token utility) 극대화·과적합 억제

주요 아이디어는 스타일·관점 다양화를 유도하는 프롬프트와 자동 재표현 + 정합성 검증으로 고품질 토큰을 확장하는 것이다.

파인튜닝 & 최적화 단계

  1. Supervised Fine‑Tuning (SFT)

    • 인‑하우스·오픈 소스 프리퍼런스·인스트럭션 세트로 초기 정렬.
    • 동시에 MuonClip(Muon Optimizer + QK‑Clip)으로 안정적 학습; QK‑Clip이 attention logit 폭주를 억제한다.

  2. Reinforcement Learning (RL)

    • RLVR (Verifiable Reward) + Self‑Critique Rubric Reward를 결합한 Self‑Critiqued Policy Optimization 프레임워크.

    • 핵심 목적식은

      $$ \mathcal{L}_{\text{RL}} = \mathbb{E}_{x\sim D}\Bigl[\tfrac1K\!\sum_{i=1}^{K}\!\bigl(r(x,y_i)-\bar r(x)-\tau\log\tfrac{\pi_\theta(y_i|x)}{\pi_{\text{old}}(y_i|x)}\bigr)^2\Bigr] $$

      로 정의되며, MuonClip으로 최적화된다.

  3. 안정성·효율 트릭

    • Budget Control: 태스크별 응답 길이 상한을 두어 토큰 낭비를 방지.
    • PTX Loss: 고품질 프리트레인 데이터(PTX)를 보존해 망각을 방지하는 보조 손실.
    • Temperature Decay: RL 초기에는 탐색적 고 temperature, 후기에는 안정적 저 temperature로 전환.

  4. 인프라 & 스케줄링

    • Partial Rollout·Colocated Architecture로 긴 상호작용 경로도 효율적으로 수집/학습.

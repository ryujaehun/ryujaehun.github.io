# 논문 원문의 표와 그림 가져오기

- 날짜: 2026-09-07
- 상태: 구현 완료 (`blog-automation` `bed6522`, 블로그 `4c08624`)
- 범위: 서브프로젝트 4. 사용법은 `automation/README.md` 의
  "논문 원문의 표와 그림". 이 문서는 **왜 그렇게 했는지**만 남긴다.

## PDF 가 아니라 e-print 를 쓴다

사용자 제안이 맞았다. `arxiv.org/e-print/<id>` 가 LaTeX 소스와 그림 원본을
그대로 준다.

| | PDF 파싱 | e-print |
|---|---|---|
| 표 | 셀 경계를 좌표로 추측 | `&` 로 명시 |
| 그림 | 페이지에서 잘라내기 | 원본 파일 그대로 |
| 캡션 | 본문과 구분 어려움 | `\caption{}` |

비교할 수준이 아니다. PDF 파싱은 시도하지 않았다.

## 표는 모델을 거치지 않는다

표의 값어치는 **숫자 그 자체**다. 모델이 옮겨 적으면 틀릴 수 있고, 그러면
"원문 값 보장" 이라는 이 기능의 목적이 없어진다. 그래서 `latex_tables.py`
가 기계적으로만 변환한다.

같은 이유로 **번역 단계가 이 절을 건드리지 않는다.** `<!-- verbatim-tables -->`
표시자로 경계를 찾아 잘라내고, 절 제목과 안내문만 영어판으로 바꿔 다시
붙인다. 구조 검사 대상에서도 빠진다 — 표 행이 수십 개라 함께 검사하면
번역문이 늘 어긋난 것처럼 보인다.

### colspan 이 없다

마크다운 표는 `\multicolumn` 을 표현하지 못한다. HTML `<table>` 로 낼
수도 있었지만, 그러면 본문에 raw HTML 이 들어가고 번역 단계의 구조
검사(`^|` 행 세기)를 HTML 까지 세도록 고쳐야 한다.

그룹 헤더를 열 이름에 접어 넣는 쪽을 택했다.

```
& \multicolumn{4}{c}{Qwen3-32B} & \multicolumn{5}{c}{Qwen2.5-7B}
Method & 8k & 16k & 32k & 64k & 64k & 128k & …
->
| Method | Qwen3-32B 8k | Qwen3-32B 16k | … | Qwen2.5-7B 64k | … |
```

구조를 조금 잃는 대신 전부 마크다운으로 유지된다.

### 실제 소스에서 걸린 것들

논문 3편(2609.03235v1, 2609.04105v1, 2609.03430v1)에 돌려 가며 만들었다.
아래는 전부 실제로 나온 문제다.

| 증상 | 원인 | 대응 |
|---|---|---|
| 헤더가 `% M \| 8k` | 소스에 옛 판의 표가 통째로 주석 처리돼 있었다 | 파싱 **전에** 주석 제거 |
| 표가 두 행으로 쪼개짐 | `\makecell{Full KV\\Heads(%)}` 의 중괄호 안 `\\` 를 행 구분자로 봤다 | 행 분리도 중괄호 인식 |
| 헤더에 `{p{.19\textwidth}X X}` | 열 정의의 중첩 중괄호를 `[^{}]*` 가 못 잡았다 | 균형 잡힌 소비로 교체 |
| 셀에 `black!7` | `\rowcolor{black!7}` 의 명령만 지우고 인자를 남겼다 | 인자까지 제거 |
| 그룹 헤더 미검출 | "숫자가 없으면 그룹 행" 으로 추측했다가 `Qwen3-32B` 에서 빗나갔다 | multicolumn 여부를 직접 추적 |

결과: 3편 45개 표에서 **LaTeX 잔여 0, 열 수 불일치 0.**

## 그림은 라이선스가 결정한다

**라이선스는 Atom API 에 없다.** OAI-PMH 에만 `<license>` 로 나온다.
이걸 모르고 올리면 침해다.

실측(게시분 8편): CC BY 4.0 3편 / arXiv 비독점 5편.

| 라이선스 | 그림 | 근거 |
|---|---|---|
| CC BY, CC0, 퍼블릭 도메인 | 가능 | 출처 표기로 충족 |
| arXiv 비독점 | 불가 | **arXiv 에게** 준 배포권이다. 제3자에게 준 게 아니다 |
| CC BY-NC\* | 불가 | `static/ads.txt` 에 AdSense 퍼블리셔 ID 가 DIRECT 로 있다 — 이 블로그는 상업적 이용이다 |
| CC BY-ND\* | 불가 | 리사이즈가 변경에 해당할 수 있다 |
| CC BY-SA\* | 불가 | SA 의무가 글 전체로 번질 수 있다 |
| 알 수 없음 | 불가 | 모르면 쓰지 않는다 |

`assets.allowed_licenses` 로 넓힐 수 있지만, 넓혀도 NC/ND/SA 는 코드에서
한 번 더 막는다. 설정 실수로 침해가 나지 않게 이중으로 뒀다.

**표는 이 게이트와 무관하다.** 사실 데이터를 다시 표현하는 것이고 출처를
밝힌다.

### 배치는 모델이 한다

그림 목록을 요약 프롬프트에 넘겨 모델이 본문 맥락에 맞는 자리에 넣게
했다. 전용 섹션에 몰아넣으면 설명된 맥락에서 멀어진다.

모델이 쓰지 않은 그림 파일은 지운다. 4장 중 2장만 쓰였는데 4장을 커밋하면
쓰이지 않는 파일이 쌓인다.

### PDF 그림

논문 그림의 대부분이 벡터 PDF 다 — 실측 12개 중 10개. 처음엔 PNG/JPG 만
받아서 편당 1~2장밖에 못 잡았고, 그러면 "적극적으로 가져오기" 가 성립하지
않았다.

`pypdfium2` 를 쓴다. **자체 포함 휠이라 poppler·ghostscript 가 필요 없다** —
CI 에 시스템 패키지를 넣지 않아도 된다. 로컬에 `pdftoppm`·`pdftocairo`·
`gs`·PyMuPDF 가 하나도 없었으므로 이 점이 결정적이었다.

### 순서

`\includegraphics` 가 나온 순서다. 논문 스스로의 서술 순서이고 첫 그림이
보통 헤드라인이다. **파일 크기 순으로 하면 안 된다** — 실측한 논문의
헤드라인 그림은 18KB 이고 부수 그림이 156KB 였다.

참조되지 않은 파일은 버린다. 소스에 남은 옛 판의 그림인 경우가 많고,
실제로 로고(`graphcore-symbol.png`)가 크기 기준만으로는 통과했다.

### 크기

`static/` 이 5.4MB 인데 논문 하나의 PNG 원본이 1.8MB 다. 그대로 넣으면
한 달에 리포가 두 배가 된다.

최대 폭 1200px + WebP quality 82, 편당 4장. 실측 122~218KB/편.
CC BY 가 40% 남짓이므로 연간 30MB 정도로 예상한다.

## 같이 고친 것

**이미 `draft: false` 인 글이 재실행으로 내려갔다.** `--publish` 없이
`summarize` 를 다시 돌렸더니 사이트에 있던 글이 초안으로 바뀌어 사라졌다.
재실행이 게시를 철회하면 안 된다 — `render.already_published()` 로 기존
상태를 보고 유지한다.

## 검증

실측(2609.04105, CC BY 4.0, 요약 재생성 5분 26초, $0.0110):

- 표 6개가 원문 캡션 그대로 붙었다.
- 그림 4장을 모델이 **전부** 본문 맥락에 맞는 자리에 넣었고, 대체
  텍스트를 한국어로 그 그림이 무엇을 보여주는지로 써 넣었다.
- `hugo --gc --minify`: `<img>` 4개, `<table>` 35개, `<h1>` 1개.
  배포 산출물에 그림 4개 모두 존재.
- 그림 188KB (원본 PNG/PDF 합계 1.0MB).
- `blog-automation` 테스트 143 → 189.

## 남은 것

- `.eps`/`.ps` 그림은 변환기가 없어 건너뛴다. 최근 논문에는 드물다.
- `table` 환경에 들어 있지 않은 `tabular`(figure·minipage 안)는 안 가져온다.
  실측 9/34/12 개 중 5/30/10 개를 가져왔고, 나머지는 주석 처리분과
  `table` 밖의 것이다.
- 부록 표가 20개 넘는 논문이 있어 `max_tables: 8` 로 잘랐다. 어느 표가
  중요한지 고르는 로직은 없다 — 나온 순서대로다.

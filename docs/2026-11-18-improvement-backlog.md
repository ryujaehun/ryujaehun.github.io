# 블로그 개선 작업 목록

2026-11-18 기준으로 Hugo 사이트, 배포 워크플로, 콘텐츠 자동화 연결부를 점검했다. P1은 독자의 기본 기능이나 게시 안정성에 영향을 주는 작업이고, P2는 영향 범위가 좁거나 운영 검증이 먼저 필요한 작업이다.

사이트 변경 5건을 `fix/blog-improvement-items` 브랜치에서 구현했다. Hugo Extended 0.165.0 빌드에서 검색 메타 오류와 깨진 내부 링크·이미지가 각각 0건이었다. PR 검증은 로컬에서 정상 빌드와 깨진 링크 입력을 확인했다. GitHub 호스팅 러너에서의 실행은 브랜치를 게시한 뒤 확인할 수 있다.

## P1 검색 로딩 실패 후 같은 화면에서 재시도 지원

검색 인덱스 요청이 한 번 실패하면 클라이언트가 빈 배열을 로딩 결과로 저장한다. 같은 페이지에서 검색창을 다시 열거나 검색어를 바꿔도 인덱스를 다시 요청하지 않고 ‘검색 결과 없음’을 표시한다. 현재 브라우저 검사는 검색창을 열고 닫는 동작을 확인한다. [검색 구현](../themes/hugo-narrow/assets/js/search.js#L325) · [브라우저 검사](../scripts/check-reading-ui.mjs#L150)

- [x] 로딩 실패를 결과 없음과 구분하고, 재시도 버튼이나 다음 입력에서 다시 요청할 수 있게 한다. 진행 중인 요청은 공유한다.
- [x] 한국어·영어 홈에서 첫 요청을 HTTP 503으로 응답시킨 뒤, 새로고침 없이 재시도하여 실제 글 링크가 나타나는지 확인한다. 정상적으로 검색 결과가 없는 경우도 검증한다.

## P1 검색 초기 다운로드 크기 줄이기

검색창을 열면 해당 언어의 전체 검색 인덱스를 받는다. 프로덕션 빌드에서 한국어 인덱스는 607건에 17.72 MiB, 영어 인덱스는 130건에 3.72 MiB였다. 로컬 gzip 압축 후에도 각각 4.99 MiB와 1.21 MiB다. 두 인덱스 모두 원본 바이트의 약 96%가 게시글 본문 필드에 해당한다. [검색 인덱스 템플릿](../layouts/index.json#L4) · [검색창 로딩 시점](../themes/hugo-narrow/assets/js/search.js#L214)

- [x] 제목·요약·태그를 우선 검색한다. 결과가 없거나 독자가 본문 검색을 요청하면 본문 인덱스를 가져온다. 기존 방식의 전체 인덱스를 gzip으로 압축한 결과와 초기 인덱스를 비교했다.
- [x] 초기 gzip 크기는 한국어 약 102 KiB, 영어 약 18 KiB로 줄었다. 기존 전체 인덱스 대비 약 98% 감소했다. 브라우저에서 제목·태그·본문 검색을 두 언어로 확인했다. 모바일 브라우저에서 캐시를 끄고 로컬 서버의 압축 전 응답을 1 MiB/s와 지연 80 ms로 제한한 단일 표본의 첫 제목 검색은 한국어 20.60초에서 0.62초, 영어 4.61초에서 0.21초로 줄었다.

## P1 PR에서 사이트 변경을 미리 검증

사이트 워크플로는 `main`에 푸시된 뒤에 Hugo 빌드, 중복 경로, 검색 메타, 내부 링크, 브라우저 검사를 실행한다. 자동 논문 게시는 게시글 마크다운을 별도로 검사한다. 레이아웃이나 설정을 바꾸는 PR에는 이 저장소의 빌드 검사가 연결되어 있지 않다. [사이트 워크플로](../.github/workflows/main.yaml#L4) · [논문 게시 검사](../automation/.github/workflows/daily.yaml#L342)

- [x] 공통 빌드와 정적 검사를 PR에서도 실행할 수 있게 한다. 공개 PR에서는 사이트 빌드에 필요한 공개 테마만 초기화하고, 검증 작업은 읽기 권한으로 실행한다.
- [ ] 정상 PR과 깨진 내부 링크를 넣은 PR에서 각각 통과와 실패를 확인한다. 배포 워크플로에서는 검증된 빌드만 게시되는지 확인한다.

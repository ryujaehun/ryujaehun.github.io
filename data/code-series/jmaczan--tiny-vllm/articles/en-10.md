## KV cache: a 2GiB fixed block pool

The KV cache is not a dynamic allocation that grows with request size like a tensor;
it is a **fixed reservation allocation** made once at program startup.
`KV_CACHE_SIZE_BYTES` is exactly 2GiB (`src/main.cpp:35`). A unit block holds two
pieces, K and V, together. K stores `BLOCK_SIZE=16` tokens × `KV_DIM=512` dimensions
in bf16 (2 bytes), and V of the same size is appended into the same block
(`V_OFFSET`, `src/main.cpp:32-34`). Thus one block is
`2 × 16 × 512 × 2 = 32768` bytes = `BLOCK_BYTES` (`:34`). Dividing the whole by this
size gives `2GiB / 32768 bytes = 65536` = `NUM_BLOCKS` (`:37`).

```
BLOCK_SIZE = 16 tokens        (src/main.cpp:32-37)
KV_DIM     = 512
bf16       = 2 bytes
K and V are stored in one block (V_OFFSET)
→ BLOCK_BYTES = 2×16×512×2 = 32768  (:34)
NUM_BLOCKS   = 2GiB / 32768 = 65536 (:35, :37)
MAX_BLOCKS_PER_SEQ = 128            (:36)
```

These constants are redefined in `src/kernels.cu` as well (`src/kernels.cu:16-19`).
The source acknowledges this duplication as a TODO (`src/kernels.cu:6`;
`evidence/claims.md:57`). The 2GiB is a reservation allocation independent of actual
usage.

The block pool is managed in three pieces (`src/main.cpp:574-581`).

```
kv_cache      : 2GiB device memory, 65536 physical block slots  (:576)
free_blocks   : stack filled with 0..65535  (:577-578)
block_table   : CPU vector, sequence×layer×MAX_BLOCKS_PER_SEQ all -1  (:579)
block_table_gpu : device buffer of the same size  (:580-581)
```

The `free_blocks` stack is responsible for "which physical block is still free," and
`block_table` for "which physical block logical block N of each sequence·layer is"
(`evidence/claims.md:51`). The logical block number is determined by its position
within the KV sequence (`seq_len / BLOCK_SIZE`), and the physical block number is
converted to a byte offset within `kv_cache`. K is at
`kv_cache + block*BLOCK_BYTES`, and V is at that position plus `V_OFFSET`
(`evidence/trace.md:105-106`, `:152`).

```
kv_cache memory layout (one physical block):
┌──────────────────────────────┬──────────────────────────────┐
│ K : 16 tokens × 512 dims bf16│ V : 16 tokens × 512 dims bf16│
│  block*BLOCK_BYTES           │  + V_OFFSET                  │
└──────────────────────────────┴──────────────────────────────┘

block_table (sequence slot, layer layer, logical block 0..127):
  slot 0 layer 0: [ 3, 7, 12, -1, -1, ... ]
                      ↑logical0 ↑logical1 ↑logical2
free_blocks: [ 4, 5, 8, ... ]  pop is the next allocation number, push returns
```

This indexing scheme is the axis of the entire chapter. What the kernel traverses is
this `block_table`, and what the scatter updates is also this `block_table`.

## KV scatter: prefill is block-wise, decode is token-wise

The way K/V is filled into the cache differs between prefill and decode. **Prefill
cuts the entire prompt into `BLOCK_SIZE` units and D2D-copies a chunk of up to BLOCK_SIZE K/V tokens (the last chunk may be partial), while decode overwrites one token at
a time at the corresponding position** (`evidence/claims.md:59-60`).

### prefill: pop a physical block for each logical block

The prefill Paged KV scatter (`src/main.cpp:247-288`) divides the prompt into
`BLOCK_SIZE` units, computes the logical block index (`:251-264`), and reads the
physical block for that logical block from `block_table`. If the value is `-1`, it
means the block is not yet allocated, so it pops from `free_blocks` and records it
(`:264-272`). If it is already not `-1`, it throws `assert(false)` (`:273-277`).
This is a branch that assumes the normal path always starts from `-1`. Afterward, K
is D2D-copied to `kv_cache + block*BLOCK_BYTES` and V to `+ V_OFFSET`, only up to a
`BLOCK_SIZE` token chunk (the last one partial) (`:280-287`).

```
prefill scatter (src/main.cpp:251-288):
  logical block = split prompt tokens into BLOCK_SIZE(16) units   (:251-264)
  block_table[slot][layer][logical block] == -1 ?
    → free_blocks.pop() → record physical block number          (:264-272)
    → otherwise assert(false)                                   (:273-277)
  D2D-copy a chunk of up to BLOCK_SIZE K/V tokens (the last chunk may be partial)  (:280-287)
```

### decode: pop only on the first token in a block

The decode Paged KV scatter (`src/main.cpp:851-873`) computes the logical block and
the position within the block from the sequence length. Logical block =
`seq_len / BLOCK_SIZE`, token within block = `seq_len % BLOCK_SIZE` (`:856-857`). It
pops from `free_blocks` only when it is the first token in the block (`% == 0`), and
otherwise overwrites at the corresponding token position of the already-assigned
physical block (`:859-865`). K/V is D2D-copied to
`kv_cache + block*BLOCK_BYTES (+ V_OFFSET) + token*KV_DIM` (`:866-872`).

```
decode scatter (src/main.cpp:851-873):
  logical block    = seq_len / BLOCK_SIZE   (:856)
  position in block = seq_len % BLOCK_SIZE  (:857)
  position == 0 ? → free_blocks.pop() → record  (:859-865)
  D2D-copy K/V to the token offset            (:866-872)
```

Both scatters are **D2D `cudaMemcpy`, not a kernel** (`evidence/claims.md:67`). Also,
the `assert(false)` branch relies on the assumption that it is not reached on the
normal path (`evidence/claims.md:67`).

## GQA: 4 Q heads share 1 K/V head

The number of K/V heads that paged attention references differs from the number of Q
heads. Q is `NUM_Q_HEADS=32`, K/V is `NUM_K_HEADS=NUM_V_HEADS=8`
(`src/main.cpp:20-23`), and inside `pagedAttentionKernel`,
`kv_head_idx = q_head_id / GQA_Q_TO_K_RATIO(=4)` means 4 Q heads share 1 K·V head
(`src/kernels.cu:468`; `src/main.cpp:23`). That is, the KV cache address computation
selects one of the 8 K/V heads, but the block_table mapping is based on
slot/layer/logical block independent of the head.

```
Q head 0..3  ──► K/V head 0      (q_head_id / 4)
Q head 4..7  ──► K/V head 1
...
Q head 28..31 ─► K/V head 7       (src/kernels.cu:468)
```

The primary ownership of this 4:1 sharing constant and indexing belongs to Chapter 5
(`briefs.md:115`), and this chapter reads `kv_head_idx` inside the kernel
(`src/kernels.cu:468`). Because the GQA ratio is hard-coded as a constant,
recompilation is required if the model structure changes (`evidence/claims.md:78`).

## pagedAttentionKernel: grid and block table traversal

The `pagedAttention` wrapper (`src/kernels.cu:525-527`) launches the kernel with grid
`(num_active_slots, NUM_Q_HEADS)`, block `HEAD_DIM=64` at the call site of the decode
layer loop (`src/main.cpp:878`) (`src/kernels.cu:525-527`). The 64 threads per block
form exactly two warps.

```
pagedAttention call (src/main.cpp:878):
  in the layer loop: KV scatter → block_table sync (:876) → call (:878)

kernel launch configuration (src/kernels.cu:525-527):
  gridDim  = (num_active_slots, NUM_Q_HEADS)
  blockDim = HEAD_DIM = 64 threads
```

The order of the kernel body (`src/kernels.cu:461-523`) is as follows.

1. **Slot·head mapping** (`:464-469`) — `blockIdx.y` is the Q head and `blockIdx.x`
   is the position within active slots. `kv_head_idx = q_head_id /
   GQA_Q_TO_K_RATIO` (`:468`). The actual sequence slot is obtained through the
   `gpu_active_slots` mapping (`:465`).
2. **Block count computation** (`:471`) — `num_blocks = (seq_len + BLOCK_SIZE - 1) /
   BLOCK_SIZE` sets the number of logical blocks to traverse.
3. **Physical block traversal** (`:478-482`) — for each logical block it looks up
   `block_table` to get the physical block number (`:480`), and loops over tokens
   within the block by `tokens_in_block` (`:481-482`).
4. **K/V read and dot product** (`:484-508`) — each thread handles 1 dimension of Q
   (`:469`), reads K·V of the physical block (`:484-485`), and computes the dot
   product with a within-warp `__shfl_down_sync` tree sum (`:489-493`). The sums of
   the two warp halves are combined via the `dot_products[2]` shared array
   (`:494-507`; `:463`).
5. **Online softmax** (`:510-519`) — updates `current_max`/`d`/`acc`
   (`:474-476`, `:510-519`) and finally outputs `acc/d` (`:522`).

The details of steps 4 and 5 are owned by Chapter 9. This chapter reads steps 1–3,
that is, **what data this kernel runs on**.

Here it must be noted that indexing is mixed between two systems. Q and `seq_len` use
`blockIdx.x` as the **position within active slots**, while the block table lookup
goes through the `gpu_active_slots` mapping to read the **actual slot**
(`src/kernels.cu:464-470`, `:480`). Because decode batches active slots together
(`src/main.cpp:722-737`; `evidence/claims.md:39`), the x-axis of the kernel grid is
0..num_active_slots-1, and `gpu_active_slots[i]` returns the actual sequence slot
number. Without this intermediate mapping, the kernel would read the `block_table` of
a non-active slot (`evidence/trace.md:235-239`).

```
indexing systems inside the kernel:
  blockIdx.x  → position within active slots (0..num_active_slots-1)   (:464-469)
  gpu_active_slots[blockIdx.x] → actual sequence slot number           (:465)
  block_table[actual slot][layer][logical block] → physical block number (:480)
  kv_cache[physical block*BLOCK_BYTES (+ V_OFFSET) + token*KV_DIM]
```

```
pagedAttentionKernel flow (src/kernels.cu:461-523):
  grid (slot, Q head), block 64 threads
  ├─ slot/head mapping: q_head_id, kv_head_id = q/4, actual slot (:464-470)
  ├─ num_blocks = ceil(seq_len / BLOCK_SIZE)              (:471)
  ├─ logical block loop:
  │    block_table[actual slot][layer][logical block] → physical block (:480)
  │    token loop for tokens_in_block                     (:481-482)
  │      K·V read → __shfl_down_sync tree sum → dot product (:484-508)
  │      online softmax: update current_max/d/acc           (:510-519)
  └─ output acc / d                                        (:522)
```

## Reading only accumulated K = causal masking

This kernel has no separate causal masking kernel or `-INFINITY` masking. Instead, it
**substitutes masking by reading only the K/V tokens already written to the cache**
(`evidence/claims.md:88`).

The traversal range is limited in two stages. First, the physical block count is set
to `num_blocks = (seq_len + BLOCK_SIZE - 1) / BLOCK_SIZE` (`:471`) so that logical
blocks to which not a single token has been written are not reached. Within that, it
traverses only `tokens_in_block = min(seq_len - logical_block_idx * BLOCK_SIZE,
BLOCK_SIZE)` (`:481-482`), skipping empty slots in the last block. If the sequence
length is 34, logical blocks 0 and 1 are read in full, and logical block 2 is read
for only 2 tokens. Tokens after 34 do not exist in this sequence, so "not reading" is
itself future-token masking.

```
seq_len = 34, BLOCK_SIZE = 16 → num_blocks = 3  (:471)
  logical0 (tokens 0-15)  logical1 (tokens 16-31)  logical2 (tokens 32-33, tokens_in_block=2)
  tokens after 34 do not exist → not reading = future masking  (:481-482)
```

Because the current decode Q computes dot products with all accumulated K from
0..seq_len-1, the read range is exactly the causal masking boundary. This agrees with
Chapter 9's note that "masking is implemented as 'not reading' without a separate
kernel" (`evidence/claims.md:88`).

## Why decode resynchronizes block_table every layer

The `block_table_gpu` that the kernel traverses is a copy of the CPU `block_table`. At
block boundaries, the KV scatter can change `block_table`, and since the copy is
executed every layer regardless of whether there was a change, the GPU side is
updated after the scatter so that the kernel sees the latest table. Thus the decode
layer loop goes through the fixed order: KV scatter (`src/main.cpp:851-873`) → full
H2D copy of `block_table_gpu` (`:876`) → `pagedAttention` call (`:878`). The
synchronization size is
`MAX_SEQUENCES*N_LAYERS*MAX_BLOCKS_PER_SEQ*sizeof(int)`, i.e. 2×16×128×4 bytes
(`evidence/claims.md:107`).

The same full synchronization also occurs at prefill end (`src/main.cpp:552`) and at
slot release (`:1030`). Slot release resets `block_table` to -1 and returns physical
blocks to `free_blocks`, so that result must also be reflected in the GPU copy
(`evidence/claims.md:104`).

```
decode layer loop (src/main.cpp:851-878):
  update block_table via KV scatter        (:851-873)
  full H2D recopy of block_table_gpu       (:876)
  pagedAttention call                      (:878)

other points where the same sync occurs:
  prefill end (:552), slot release (:1030)
```

The source acknowledges this full recopy as a TODO ("do it more clever and not copy
full table unnecessarily", `src/main.cpp:551`). Copying the full table every layer is
a cost that occurs because the table size is fixed even when the batch is small
(`evidence/claims.md:110`).

## Limitations

- **Claim 8 — `dot_products[2]`'s dependency on `HEAD_DIM=64`** — the current
  `HEAD_DIM=64` launch creates exactly two full warps (`src/kernels.cu:525-527`). The
  HEAD_DIM-dependent reduction structure is the shfl offsets (`:489-493`), the
  thread 0/32 branches (`:494-501`), and `dot_products[2]` (`:463`). `WARP_FULL_MASK`
  is a separate fixed constant representing the entire warp (`src/cuda_to_hip.h:50`,
  `:59`). If `HEAD_DIM` changes, the validity of the reduction structure and mask
  usage must be reviewed together and recompiled.
- **Claim 6 — the scatter is not a kernel** — the prefill and decode scatters are all
  D2D `cudaMemcpy`. The `assert(false)` branch assumes it is not reached on the
  normal path (`evidence/claims.md:67`).
- **Claim 5 — constant duplication and reservation allocation** — `BLOCK_SIZE`,
  `V_OFFSET`, `BLOCK_BYTES`, etc. are defined redundantly in `main.cpp` and
  `kernels.cu`, and the source acknowledges this as a TODO (`src/kernels.cu:6`,
  `:8-19`). The 2GiB is reserved all at once regardless of usage
  (`evidence/claims.md:57`).
- **Claim 10 — full table recopy** — decode H2D-recopies the entire
  `block_table_gpu` (2×16×128×4 bytes) every layer. The source acknowledges this cost
  as a TODO (`src/main.cpp:551`; `evidence/claims.md:110`).
- **Numerical accuracy unverified** — the correctness of the block scatter and the
  paged attention kernel is not confirmed by tests within the ranges cited by this
  chapter. The only kernel test is `tests/test_softmax.cu`, and the repository was not
  executed (`evidence/recon.md:4`, `:12`, `:38`).
- **No performance claims** — how much memory the paged approach saves and how much
  the full recopy affects execution time have no basis in Claims 1–10 and are not
  written.

## Summary

This chapter read the last point of the series, paged attention where data structures
and kernel design meet. The KV cache is reserved all at once as a 2GiB fixed block
pool (`src/main.cpp:35`, `:576`), and the `free_blocks` stack and the CPU
`block_table` (initialized entirely to -1) handle the logical block → physical block
mapping (`:577-581`). Prefill pops for each logical block and D2D-copies a chunk of up to BLOCK_SIZE tokens (the last chunk may be partial) (`:251-288`), while decode pops only on
the first token in a block and overwrites at the token position (`:851-873`).

`pagedAttentionKernel` runs with grid `(num_active_slots, NUM_Q_HEADS)`, block
`HEAD_DIM=64` (`src/kernels.cu:525-527`), finds the actual slot through the
`gpu_active_slots` mapping (`:465`), and traverses physical blocks following
`block_table` (`:480`). By not reading tokens beyond `seq_len`, it substitutes causal
masking (`:471`, `:481-482`), and each Q computes its dot product with accumulated K
via a warp tree sum and passes through online softmax (`:489-519`). The reason the
kernel can read this data structure is that decode copies the entire CPU `block_table` to `block_table_gpu` via H2D after the KV scatter in every layer (`src/main.cpp:876`,
`:552`, `:1030`).

Prefill D2D-copies a chunk of up to BLOCK_SIZE tokens (the last chunk may be partial), and
decode overwrites token by token. The 4:1 GQA is applied when
`pagedAttentionKernel` selects one of the 8 K/V heads in the K/V address computation
(`src/kernels.cu:468`). Meanwhile, the `block_table` mapping connects
slot/layer/logical block to physical block independent of the head (`:480`). The two
axes are distinct, and separating logical block from physical storage is the core of
this structure.

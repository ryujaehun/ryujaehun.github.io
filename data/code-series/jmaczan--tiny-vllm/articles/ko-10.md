# tiny-vllm 10장 · paged KV cache와 paged attention

9장은 `pagedAttentionKernel`(`src/kernels.cu:461-523`) 안에서 attention 스코어를
확률로 바꾸는 online softmax와 warp 트리 합을 읽고, 블록 테이블 순회와 그리드 구성을
이 장으로 넘겼다. 이 장은 그 나머지 절반과, 커널이 읽어 들이는 입력 데이터 구조를
함께 읽는다. KV 캐시가 **물리 블록 풀**로 어떻게 나뉘고(`Claim 5`), 그 블록이
**논리 블록→물리 블록 테이블**로 어떻게 매핑되며(`Claim 5`, `Claim 10`), 그 테이블을
따라 커널이 물리 블록을 순회해 attention을 계산하는지(`Claim 8`)가 이 장의 골격이다.
시리즈 서사가 "paged attention을 데이터 구조와 커널 설계가 만나는 지점"으로 끝맺는
위치다(`guide.md:24-29`).

이 장의 주 소유 주장은 Claim 8이다. Claim 5·6·7·10은 이 커널의 입력과 호출 조건을
만드는 참조·소유 주장이다(`evidence/claims.md:80-88`, `:49-57`, `:59-67`, `:69-78`,
`:102-110`). 시리즈의 증거 규칙대로 모든 기술 주장은 고정 커밋
`1896ff5c37a241050dbcd9527caf9dc1d3087a61`의 소스 경로와 줄 범위로 인용한다
(`guide.md:5-9`, `:11-16`).

## KV 캐시: 2GiB 고정 블록 풀

KV 캐시는 텐서처럼 요청 크기에 맞춰 늘어나는 동적 할당이 아니라, 프로그램 시작 때
한 번에 고정 크기로 잡는 **고정 예약 할당**이다. `KV_CACHE_SIZE_BYTES`는 정확히
2GiB다(`src/main.cpp:35`). 단위 블록은 K와 V 두 조각을 함께 담는다. K는
`BLOCK_SIZE=16` 토큰 × `KV_DIM=512` 차원을 bf16(2바이트)으로 저장하고, V도 같은
크기로 한 블록에 이어붙는다(`V_OFFSET`, `src/main.cpp:32-34`). 그래서 블록
하나는 `2 × 16 × 512 × 2 = 32768`바이트 = `BLOCK_BYTES`가 된다(`:34`). 이 크기로
전체를 나누면 `2GiB / 32768바이트 = 65536`개 = `NUM_BLOCKS`다(`:37`).

```
BLOCK_SIZE = 16 토큰        (src/main.cpp:32-37)
KV_DIM     = 512
bf16       = 2바이트
K와 V가 한 블록에 담김 (V_OFFSET)
→ BLOCK_BYTES = 2×16×512×2 = 32768  (:34)
NUM_BLOCKS   = 2GiB / 32768 = 65536 (:35, :37)
MAX_BLOCKS_PER_SEQ = 128            (:36)
```

이 상수들은 `src/kernels.cu`에도 다시 정의돼 있다(`src/kernels.cu:16-19`). 소스는 이
중복을 TODO로 인지하고 있다(`src/kernels.cu:6`; `evidence/claims.md:57`). 2GiB는
실제 사용량과 무관한 예약 할당이다.

블록 풀은 세 조각으로 관리된다(`src/main.cpp:574-581`).

```
kv_cache      : 2GiB 디바이스 메모리, 65536개 물리 블록 슬롯  (:576)
free_blocks   : 0..65535로 채워진 스택  (:577-578)
block_table   : CPU 벡터, 시퀀스×레이어×MAX_BLOCKS_PER_SEQ 전부 -1  (:579)
block_table_gpu : 같은 크기의 디바이스 버퍼  (:580-581)
```

`free_blocks` 스택이 "어느 물리 블록이 아직 빈지"를, `block_table`이 "각 시퀀스·레이어의
논리 블록 N이 어느 물리 블록인지"를 담당한다(`evidence/claims.md:51`). 논리 블록 번호는
KV 시퀀스 내 위치(`seq_len / BLOCK_SIZE`)로 정해지고, 물리 블록 번호는 `kv_cache`
안의 바이트 오프셋으로 환산된다. K는 `kv_cache + block*BLOCK_BYTES`, V는 여기에
`V_OFFSET`을 더한 위치다(`evidence/trace.md:105-106`, `:152`).

```
kv_cache 메모리 배치 (물리 블록 하나):
┌──────────────────────────────┬──────────────────────────────┐
│ K : 16토큰 × 512차원 bf16    │ V : 16토큰 × 512차원 bf16    │
│  block*BLOCK_BYTES           │  + V_OFFSET                  │
└──────────────────────────────┴──────────────────────────────┘

block_table (시퀀스 slot, 레이어 layer, 논리 블록 0..127):
  slot 0 layer 0: [ 3, 7, 12, -1, -1, ... ]
                     ↑논리0 ↑논리1 ↑논리2
free_blocks: [ 4, 5, 8, ... ]  pop이 다음 할당 번호, push가 반환
```

이 인덱싱 체계가 이 장 전체의 축이다. 커널이 순회하는 것은 이 `block_table`이고,
산포가 갱신하는 것도 이 `block_table`이다.

## KV 산포: prefill은 블록 단위, decode는 토큰 단위

캐시에 K/V를 채우는 방식은 prefill과 decode가 다르다. **prefill은 프롬프트 전체를
`BLOCK_SIZE` 단위로 잘라 최대 `BLOCK_SIZE` 토큰 청크(마지막은 일부)만 D2D 복사하고, decode는 한 토큰씩 해당 위치에 덮어쓴다**
(`evidence/claims.md:59-60`).

### prefill: 논리 블록마다 물리 블록을 pop

prefill의 Paged KV 산포(`src/main.cpp:247-288`)는 프롬프트를 `BLOCK_SIZE` 단위로
나눠 논리 블록 인덱스를 계산하고(`:251-264`), `block_table`에서 그 논리 블록의 물리
블록을 읽는다. 값이 `-1`이면 아직 할당되지 않았다는 뜻이므로 `free_blocks`에서 pop해
기록한다(`:264-272`). 이미 `-1`이 아니면 `assert(false)`를 던진다(`:273-277`).
정상 경로에서는 항상 `-1`에서 시작한다고 가정하는 분기다. 이후 K를
`kv_cache + block*BLOCK_BYTES`, V를 `+ V_OFFSET`에 최대 `BLOCK_SIZE` 토큰 청크(마지막은 일부)만 D2D 복사한다
(`:280-287`).

```
prefill 산포 (src/main.cpp:251-288):
  논리 블록 = prompt 토큰을 BLOCK_SIZE(16) 단위로 분할   (:251-264)
  block_table[slot][layer][논리 블록] == -1 ?
    → free_blocks.pop() → 물리 블록 번호 기록          (:264-272)
    → 아니면 assert(false)                              (:273-277)
  K/V 최대 BLOCK_SIZE 토큰 청크(마지막은 일부)만 D2D 복사                             (:280-287)
```

### decode: 블록 내 첫 토큰일 때만 pop

decode의 Paged KV 산포(`src/main.cpp:851-873`)는 시퀀스 길이에서 논리 블록과 블록 내
위치를 계산한다. 논리 블록 = `seq_len / BLOCK_SIZE`, 블록 내 토큰 =
`seq_len % BLOCK_SIZE`다(`:856-857`). 블록 내 첫 토큰(`% == 0`)일 때만
`free_blocks`에서 pop하고, 그 외에는 이미 배정된 물리 블록의 해당 토큰 위치에
덮어쓴다(`:859-865`). K/V는 `kv_cache + block*BLOCK_BYTES (+ V_OFFSET) +
token*KV_DIM` 위치로 D2D 복사된다(`:866-872`).

```
decode 산포 (src/main.cpp:851-873):
  논리 블록   = seq_len / BLOCK_SIZE   (:856)
  블록 내 위치 = seq_len % BLOCK_SIZE  (:857)
  위치 == 0 ? → free_blocks.pop() → 기록  (:859-865)
  K/V를 토큰 오프셋에 D2D 복사            (:866-872)
```

두 산포 모두 **커널이 아니라 D2D `cudaMemcpy`**다(`evidence/claims.md:67`). 또한
`assert(false)` 분기는 정상 경로에서 도달하지 않는다는 가정에 의존한다
(`evidence/claims.md:67`).

## GQA: 4개 Q 헤드가 1개 K/V 헤드를 공유

paged attention이 참조하는 K/V 헤드 수는 Q 헤드 수와 다르다. Q는 `NUM_Q_HEADS=32`,
K/V는 `NUM_K_HEADS=NUM_V_HEADS=8`이고(`src/main.cpp:20-23`), `pagedAttentionKernel`
내부에서 `kv_head_idx = q_head_id / GQA_Q_TO_K_RATIO(=4)`로 4개 Q 헤드가 1개의
K·V 헤드를 공유한다(`src/kernels.cu:468`; `src/main.cpp:23`). 즉 KV cache 주소 계산은 8개 K/V heads 중 하나를 선택하지만, block_table mapping은
head와 무관하게 slot/layer/logical block 기준이다.

```
Q 헤드 0..3  ──► K/V 헤드 0      (q_head_id / 4)
Q 헤드 4..7  ──► K/V 헤드 1
...
Q 헤드 28..31 ─► K/V 헤드 7       (src/kernels.cu:468)
```

이 4:1 공유 상수와 인덱싱의 주 소유는 5장이고(`briefs.md:115`), 이 장은 커널 내
`kv_head_idx`(`src/kernels.cu:468`)를 읽는다. GQA 비율이 상수로 박혀 있어 모델 구조가
바뀌면 재컴파일이 필요하다(`evidence/claims.md:78`).

## pagedAttentionKernel: 그리드와 블록 테이블 순회

`pagedAttention` 래퍼(`src/kernels.cu:525-527`)는 decode 레이어 루프의 호출 지점
(`src/main.cpp:878`)에서 그리드 `(num_active_slots, NUM_Q_HEADS)`, 블록
`HEAD_DIM=64`로 커널을 띄운다(`src/kernels.cu:525-527`). 블록당 스레드 64개는 정확히
두 개의 warp을 만든다.

```
pagedAttention 호출 (src/main.cpp:878):
  레이어 루프에서 KV 산포 → block_table 동기화(:876) → 호출(:878)

커널 실행 구성 (src/kernels.cu:525-527):
  gridDim  = (num_active_slots, NUM_Q_HEADS)
  blockDim = HEAD_DIM = 64 스레드
```

커널 본문(`src/kernels.cu:461-523`)의 순서는 다음과 같다.

1. **슬롯·헤드 매핑**(`:464-469`) — `blockIdx.y`가 Q 헤드, `blockIdx.x`가 활성 슬롯 내
   위치다. `kv_head_idx = q_head_id / GQA_Q_TO_K_RATIO`(`:468`). 실제 시퀀스 슬롯은
   `gpu_active_slots` 매핑을 거쳐 얻는다(`:465`).
2. **블록 수 계산**(`:471`) — `num_blocks = (seq_len + BLOCK_SIZE - 1) / BLOCK_SIZE`
   로 순회할 논리 블록 수를 잡는다.
3. **물리 블록 순회**(`:478-482`) — 논리 블록마다 `block_table`을 조회해 물리 블록
   번호를 얻고(`:480`), 블록 안에서 `tokens_in_block`만큼 토큰 루프를 돈다(`:481-482`).
4. **K/V 읽기와 dot product**(`:484-508`) — 각 스레드가 Q의 1차원을 담당하고
   (`:469`), 물리 블록의 K·V를 읽어(`:484-485`) warp 내 `__shfl_down_sync` 트리 합으로
   dot product를 구한다(`:489-493`). 두 warp 절반의 합은 `dot_products[2]` shared
   배열로 결합된다(`:494-507`; `:463`).
5. **온라인 softmax**(`:510-519`) — `current_max`/`d`/`acc`를 갱신하고(`:474-476`,
   `:510-519`) 마지막에 `acc/d`를 출력한다(`:522`).

이 중 4·5단계의 상세는 9장이 소유한다. 이 장은 1~3단계, 곧 **어떤 데이터로 이 커널이
도는지**를 읽는다.

여기서 인덱싱이 두 체계로 섞여 있음을 짚어야 한다. Q와 `seq_len`은 `blockIdx.x`를
**활성 슬롯 내 위치**로 쓰고, 블록 테이블 조회는 `gpu_active_slots` 매핑을 거쳐
**실제 슬롯**으로 읽는다(`src/kernels.cu:464-470`, `:480`). decode가 활성 슬롯을
묶어 배치 처리하므로(`src/main.cpp:722-737`; `evidence/claims.md:39`) 커널 그리드의
x축은 0..num_active_slots-1이고, `gpu_active_slots[i]`가 실제 시퀀스 슬롯 번호를
돌려준다. 이 중간 매핑이 없다면 커널이 활성 슬롯이 아닌 슬롯의 `block_table`을 읽게
된다(`evidence/trace.md:235-239`).

```
커널 내 인덱싱 체계:
  blockIdx.x  → 활성 슬롯 내 위치 (0..num_active_slots-1)   (:464-469)
  gpu_active_slots[blockIdx.x] → 실제 시퀀스 슬롯 번호       (:465)
  block_table[실제 슬롯][레이어][논리 블록] → 물리 블록 번호   (:480)
  kv_cache[물리 블록*BLOCK_BYTES (+ V_OFFSET) + 토큰*KV_DIM]
```

```
pagedAttentionKernel 흐름 (src/kernels.cu:461-523):
  grid (슬롯, Q헤드), block 64스레드
  ├─ 슬롯/헤드 매핑: q_head_id, kv_head_id = q/4, 실제 슬롯 (:464-470)
  ├─ num_blocks = ceil(seq_len / BLOCK_SIZE)              (:471)
  ├─ 논리 블록 루프:
  │    block_table[실제 슬롯][레이어][논리 블록] → 물리 블록 (:480)
  │    tokens_in_block 만큼 토큰 루프                     (:481-482)
  │      K·V 읽기 → __shfl_down_sync 트리 합 → dot product (:484-508)
  │      online softmax: current_max/d/acc 갱신           (:510-519)
  └─ acc / d 출력                                        (:522)
```

## 누적 K만 읽음 = causal masking

이 커널에는 causal 마스킹용 별도 커널이나 `-INFINITY` 마스킹이 없다. 대신 **이미
캐시에 쓴 K/V 토큰만 읽는 방식**으로 마스킹을 대신한다(`evidence/claims.md:88`).

순회 범위가 두 단계로 제한된다. 먼저 물리 블록 수는 `num_blocks = (seq_len +
BLOCK_SIZE - 1) / BLOCK_SIZE`로 잡아(`:471`) 아직 한 토큰도 쓰지 않은 논리 블록에
도달하지 않는다. 그 안에서도 `tokens_in_block = min(seq_len - logical_block_idx *
BLOCK_SIZE, BLOCK_SIZE)`만큼만 순회해(`:481-482`) 마지막 블록의 빈 슬롯을 건너뛴다.
시퀀스 길이가 34라면 논리 블록 0·1은 전부, 논리 블록 2는 토큰 2개만 읽는다. 토큰
34 이후는 이 시퀀스에 존재하지 않으므로 "읽지 않음"이 곧 미래 토큰 마스킹이다.

```
seq_len = 34, BLOCK_SIZE = 16 → num_blocks = 3  (:471)
  논리0(토큰 0-15)  논리1(토큰 16-31)  논리2(토큰 32-33, tokens_in_block=2)
  토큰 34 이후는 존재하지 않음 → 읽지 않음 = 미래 마스킹  (:481-482)
```

현재 decode Q가 0..seq_len-1의 모든 누적 K와 내적을 구하므로, 읽는 범위가 곧 causal
마스킹 경계가 된다. 9장이 이 특성에 "마스킹은 별도 커널 없이 '읽지 않음'으로
구현된다"고 적은 것과 일치한다(`evidence/claims.md:88`).

## decode가 매 레이어 block_table을 재동기화하는 이유

커널이 순회하는 `block_table_gpu`는 CPU `block_table`의 사본이다. 블록 경계에서는
KV 산포가 `block_table`을 바꿀 수 있고, 복사는 변화 여부와 무관하게 매 레이어 실행되므로
커널이 최신 테이블을 보도록 산포 후 GPU 쪽을 갱신한다. 그래서 decode 레이어 루프는 KV 산포(`src/main.cpp:851-873`) →
`block_table_gpu` 전체 H2D 복사(`:876`) → `pagedAttention` 호출(`:878`) 순서를
고정으로 거친다. 동기화 크기는 `MAX_SEQUENCES*N_LAYERS*MAX_BLOCKS_PER_SEQ*sizeof(int)`
즉 2×16×128×4바이트다(`evidence/claims.md:107`).

동일한 전체 동기화는 prefill 종료 시에도(`src/main.cpp:552`), 슬롯 해제 시에도
(`:1030`) 발생한다. 슬롯 해제는 `block_table`을 -1로 되돌리고 물리 블록을
`free_blocks`에 반환하므로, 그 결과도 GPU 사본에 반영돼야 한다
(`evidence/claims.md:104`).

```
decode 레이어 루프 (src/main.cpp:851-878):
  KV 산포로 block_table 갱신        (:851-873)
  block_table_gpu 전체 H2D 재복사    (:876)
  pagedAttention 호출                (:878)

같은 동기화가 일어나는 다른 지점:
  prefill 종료 (:552), 슬롯 해제 (:1030)
```

소스는 이 전체 재복사를 TODO로 인지한다("do it more clever and not copy full table
unnecessarily", `src/main.cpp:551`). 매 레이어 전체 테이블을 복사하는 것은 배치가
작아도 테이블 크기가 고정이라 일어나는 비용이다(`evidence/claims.md:110`).

## 정리

이 장은 시리즈의 마지막 지점, 데이터 구조와 커널 설계가 만나는 paged attention을
읽었다. KV 캐시는 2GiB 고정 블록 풀(`src/main.cpp:35`, `:576`)로 한 번에 예약되고,
`free_blocks` 스택과 CPU `block_table`(전부 -1 초기화)이 논리 블록→물리 블록 매핑을
담당한다(`:577-581`). prefill은 논리 블록마다 pop해 최대 BLOCK_SIZE 토큰 청크(마지막은 일부)만 D2D 복사하고(`:251-288`),
decode는 블록 내 첫 토큰일 때만 pop해 토큰 위치에 덮어쓴다(`:851-873`).

`pagedAttentionKernel`은 그리드 `(num_active_slots, NUM_Q_HEADS)`, 블록
`HEAD_DIM=64`로 실행되며(`src/kernels.cu:525-527`), `gpu_active_slots` 매핑으로 실제
슬롯을 찾고(`:465`) `block_table`을 따라 물리 블록을 순회한다(`:480`). `seq_len`을
넘는 토큰은 읽지 않음으로써 causal 마스킹을 대신하고(`:471`, `:481-482`), 각 Q는
누적 K와의 dot product를 warp 트리 합으로 구해 온라인 softmax를 거친다(`:489-519`).
커널이 이 데이터 구조를 읽을 수 있는 것은 decode가 매 레이어 KV 산포 후
`block_table_gpu` 전체를 H2D로 재동기화하기 때문이다(`src/main.cpp:876`, `:552`,
`:1030`).

prefill은 최대 `BLOCK_SIZE` 토큰 청크(마지막은 일부)만 D2D 복사하고, decode는 토큰 단위로 덮어쓴다.
GQA의 4:1은 `pagedAttentionKernel`이 K/V 주소 계산에서 8개 K/V 헤드 중 하나를 선택할
때 적용된다(`src/kernels.cu:468`). 반면 `block_table` mapping은 head와 무관하게
slot/layer/logical block을 physical block으로 연결한다(`:480`). 두 축은 구분되어 있으며,
logical block과 physical storage를 분리하는 것이 이 구조의 핵심이다.

# tiny-vllm 4장 · RMSNorm, RoPE, GEMM으로 만드는 transformer block

3장은 임베딩된 `hidden_state`를 레이어 루프의 입구에 두고 끝났다
(`src/main.cpp:158-163`). 4장은 그 입구와 로짓 출구 사이를 잇는 가운데,
`hidden_state`가 16개 레이어를 통과하며 거치는 rmsNorm·RoPE·GEMM 계산을
따라간다. attention과 KV 산포는 레이어 순서의 일부로만 등장하고 상세는 5장,
paged attention 커널은 10장으로 넘긴다.

이 장의 구현 주장은 세 갈래로 모인다. cuBLAS 전치 트릭이 Claim 2(주 소유),
레이어별 계산 순서가 Claim 3(주 소유), Q/K/V 헤드 수와 GQA 비율 상수가
Claim 7(참조)이다. 시리즈의 증거 규칙대로 모든 주장은 고정 커밋의 소스 경로와
줄 범위로 인용한다(`guide.md:11-16`).

## 이 장이 다루는 파일과 범위

`series.yaml` 4장의 대상 파일은 `src/main.cpp`와 `src/kernels.cu`다
(`series.yaml:13-15`). 레이어 루프는 `src/main.cpp:164-492`에 있고, `layer =
0..15`로 16개 레이어를 돈다(`evidence/trace.md:94`). 그 안의 GEMM은 cuBLAS,
rmsNorm·RoPE·silu·residual은 `src/kernels.cu`의 커널 래퍼를 호출한다. 최종
rmsNorm → 로짓 GEMM → CPU argmax 구간은 `:494-548`다.

이 장은 "레이어를 통과하는 계산의 순서와 각 단계의 형태"를 다룬다. attention
스코어가 어떻게 계산·마스킹·소프트맥스되는지, KV가 캐시에 어떻게 산포되는지의
상세는 5장으로, paged attention 커널은 10장으로 넘긴다. decode 루프가 같은
블록 구조를 배치로 처리하는 방식은 6장 이후의 주제다.

## 레이어 파이프라인 개관

prefill의 레이어 루프는 Claim 3이 기록한 순서를 따른다: 입력 rmsNorm → Q/K/V
GEMM → rope → paged KV 산포 → 헤드별 attention 스코어 GEMM → causalMask →
softmax → scores×V → o_proj → residual → post-attn rmsNorm → SwiGLU MLP →
residual, 그리고 최종 rmsNorm 후 로짓 GEMM(`evidence/claims.md:28`). 이 순서를
단계별 근거 줄과 함께 그리면 다음과 같다.

```
layer = 0..15 (:164-492)
 ├─ rmsNorm (입력)        :166     ── kernels.cu:84-94, 커널 :55-81
 ├─ Q 투영 GEMM           :177-196 ── Claim 2
 ├─ K/V 투영 GEMM         :201-240
 ├─ rope                  :244-245 ── kernels.cu:202-222, 커널 :173-200
 ├─ KV 산포               :247-288 ── 5장
 ├─ attention             :301-371 ── 5장
 │    스코어 :301-327 / causalMask :329 / softmax :331 / scores×V :343-371
 ├─ o_proj GEMM           :377-396
 ├─ residualAdd           :399     ── kernels.cu:319-329, 커널 :311-316
 ├─ post-attn rmsNorm     :401
 └─ SwiGLU MLP            :414-492
      gate :414-432 / up :435-453 / silu :459 / down :470-489 / residualAdd :492
최종 rmsNorm :494 → 로짓 GEMM :509-527 → D2H :529 → CPU argmax :533-543
```

이 순서는 두 반쪽으로 나뉜다. attention 이전은 "입력을 질의 가능한 형태로
만드는" 전반부(정규화·투영·위치 회전), attention 이후는 "헤드 출력을 합치고
다시 변형하는" 후반부(투영·잔차·MLP)다. 이 장은 전반부를 각각 열고, 후반부를
이어서 읽는다. attention 자체는 헤드 수와 GQA 상수만 미리 확인하고 5장으로
넘긴다.

## rmsNorm: 레이어마다 두 번, 마지막에 한 번

RMSNorm은 입력 벡터의 제곱 평균의 제곱근(RMS)으로 벡터를 나누어 단위 크기로
정규화한 뒤, 학습된 가중치로 요소별 스케일을 다시 주는 정규화 연산이다.
transformer에서는 attention 전과 MLP 전 두 곳에 적용하는 "pre-norm" 구조가
흔한데, 이 저장소도 레이어마다 두 번 같은 위치에서 호출한다.

레이어 루프 안의 호출 지점은 세 곳이다.

- **입력 rmsNorm** — `src/main.cpp:166`. attention 블록을 지나기 전
  `hidden_state`를 정규화한다.
- **post-attn rmsNorm** — `src/main.cpp:401`. attention 출력과 잔차를 합친 뒤
  MLP를 지나기 전에 다시 정규화한다.
- **최종 rmsNorm** — `src/main.cpp:494`. 레이어 루프가 끝난 뒤, 로짓 GEMM을
  지나기 전의 마지막 정규화다.

래퍼 `src/kernels.cu:84-94`와 커널 `:55-81`이 호출된다(`evidence/trace.md:95`).
가중치는 2장에서 오프셋으로 배정한 레이어별 `input_layernorm`,
`post_attention_layernorm`, 그리고 최종 `norm` 포인터다(`src/main.cpp:132-145`).
이 장은 rmsNorm 커널의 내부 스레드 구성을 줄 단위로 분해해 인용하지 않는다.
`evidence`가 래퍼와 커널의 범위만 기록하기 때문이다.

## Q/K/V 투영과 cuBLAS 전치 트릭

self-attention은 입력을 세 개의 투영으로 나눈다. 쿼리(Q)·키(K)·값(V)이며,
각각 레이어별 `w_q`/`w_k`/`w_v` 가중치를 곱해 얻는다(가중치 배정은 2장,
`src/main.cpp:132-145`). 여기서 이 장의 중심 주제인 cuBLAS 호출 방식이
등장한다.

cuBLAS는 기본적으로 열-주(column-major) 메모리를 전제한다. 반면 이 저장소의
텐서는 행-주(row-major)다. 토큰 임베딩 `inputs`는 (토큰 수, 2048) 행으로, 한
행이 토큰 하나의 2048차원 벡터다. 이 행-주 메모리를 cuBLAS에 그대로 넘기면,
cuBLAS는 같은 바이트를 열-주 행렬로 읽으므로 수학적으로 전치된 행렬로 보게
된다. Claim 2는 이 읽기 관점을 역이용한다(`evidence/claims.md:18`).

`src/main.cpp:168-176`의 주석이 전치 트릭 원리를 정리한다. Q 투영 호출은
가중치 `w_q`에 `CUBLAS_OP_T`, 입력에 `CUBLAS_OP_N`을 지정하고 `m=
EMBEDDING_LENGTH, n=prompt_len, k=EMBEDDING_LENGTH`로 걸린다(`:177-196`).
가중치를 전치해서 곱하되 입력은 그대로 두는 이 조합이 Claim 2가 요약하는
`Q^T = w_q^T * inputs` 형태다(`evidence/claims.md:18`, `evidence/claims.md:23`).

```
행-주 메모리로 저장된 두 텐서
  w_q     : (2048 × 2048)          inputs : (prompt_len × 2048)

cuBLAS 호출 (:177-196)
  A = w_q,    op = CUBLAS_OP_T  ── 읽으면서 전치
  B = inputs, op = CUBLAS_OP_N  ── 그대로
  m = 2048, n = prompt_len, k = 2048

계산 결과 C = w_q^T · inputs      열-주 (2048 × prompt_len) 로 저장
  │  행-주로 재해석
  ▼
Q : 행-주 (prompt_len × 2048)     ← 원하는 출력, 전치 불필요
```

결과 행렬 C는 (EMBEDDING_LENGTH, prompt_len) 크기로 열-주에 쓰인다. 이 메모리를
행-주로 다시 읽으면 (prompt_len, EMBEDDING_LENGTH), 곧 각 토큰 행이 2048차원
Q 벡터인 원하는 출력이다. 그래서 출력을 다시 전치하지 않아도 된다. Claim 2가
"출력을 다시 전치하지 않아도 되는 것이 이 트릭의 핵심"이라고 적는 대목이다
(`evidence/claims.md:18`).

K/V 투영은 같은 트릭에 `m=KV_DIM`으로 걸린다(`:201-219`, `:222-240`;
`evidence/trace.md:99`). Q는 2048차원, K/V는 512차원으로 나오는데, 이 크기는
뒤의 GQA 헤드 구성(32헤드×64, 8헤드×64)과 이어진다. 투영 결과는 버퍼에
나눠 담긴다. Q 출력은 `buf_2048_1`(attn_scores_v와 공유, `src/main.cpp:628-629`),
K와 V는 `k_proj_temp_buf`·`v_proj_temp_buf`(`:636`, `:639`)다
(`evidence/trace.md:74-75`, `:79-80`).

## RoPE: 위치 정보를 회전으로

RoPE는 Q/K 벡터의 차원 쌍을 위치에 의존하는 각도만큼 회전시켜, attention이
상대 위치를 쓸 수 있게 하는 변환이다. 짝수·홀수 차원이 한 쌍을 이루고, 위치
`pos`의 각도는 `pos × inv_freq`로 주어진다. 이 저장소는 각도 테이블을 미리
계산해 GPU에 올려 두고 커널이 인덱스로 읽는다.

테이블은 `main`의 `init_rope_frequencies(HEAD_DIM, MAX_SEQ_LEN, 500000, 32, 1,
4, 8192)` 호출로 준비된다(`src/main.cpp:572`). 함수(`src/kernels.cu:96-152`)는
`inv_freq` 계산 후 Llama3 NTK 스케일링을 적용하고(`:100-124`), 디바이스에
`d_inv_freq`를 복사한 뒤(`:126-127`), `cos_table`/`sin_table`을
`[max_seq_len, head_dim]` 크기로 만들어 각 (pos, i)에서
`cos/sin(pos*inv_freq)`를 짝수·홀수 요소에 중복 저장한다(`:129-144`). 전역
포인터 `d_inv_freq`/`d_cos_table`/`d_sin_table`(`:22-24`)이 이후 rope에서
읽힌다(`evidence/trace.md:48-58`).

prefill 레이어 안에서는 Q와 K에 각각 적용된다.

- `rope(q_proj, prompt_len, 2048)` — `src/main.cpp:244`.
- `rope(k_proj_temp_buf, prompt_len, 512)` — `src/main.cpp:245`.

래퍼 `src/kernels.cu:202-222`, 커널 `:173-200`이 호출된다
(`evidence/trace.md:100-101`). 호출 인자의 차원(2048, 512)이 Q는 32헤드, K는
8헤드의 헤드당 64차원(`HEAD_DIM`)이라는 GQA 구성과 맞물리는 지점이다.

## attention 자리와 GQA 상수

레이어 순서상 attention은 스코어 GEMM → causalMask → softmax → scores×V로
이어진다(`src/main.cpp:301-371`). 이 장은 순서만 확인하고 상세는 5장으로
넘긴다. 다만 Claim 7(참조)의 상수만 미리 두 가지 확인해 둔다
(`evidence/claims.md:71`).

- Q는 32개 헤드, K/V는 8개 헤드다: `NUM_Q_HEADS=32`, `NUM_K_HEADS=
  NUM_V_HEADS=8`(`src/main.cpp:20-24`).
- 4개 Q 헤드가 1개 K/V 헤드를 공유한다: `GQA_Q_TO_K_RATIO=4`
  (`src/main.cpp:23`). prefill의 스코어 GEMM은 `k_head_idx = i / GQA_Q_TO_K_RATIO`
  (`:303`), scores×V GEMM은 `v_head_idx = i / GQA_ATTN_SCORES_TO_V_RATIO`
  (`:346`)로 헤드를 매핑한다(`evidence/claims.md:74-76`).
- 스코어 스케일 상수 `attn_alpha = 1/8`이 `:649`에 정의되어 스코어 GEMM에
  쓰인다(`evidence/trace.md:108-110`).

이 GQA 매핑이 Q 투영의 2048차원 출력과 K/V 투영의 512차원 출력을 연결하는
규칙이다. 이 규칙이 실제 스코어 계산·마스킹·softmax에 어떻게 드러나는지는
5장에서 읽는다.

## o_proj와 residual

attention 블록의 출력은 각 헤드 결과를 모아 다시 2048차원으로 투영하는
`o_proj` GEMM을 거친다(`src/main.cpp:377-396`). 투영 결과는 `buf_2048_2`에
쓰인다(`:656-657`; `evidence/trace.md:116-117`).

이어서 `residualAdd`가 attention 블록 출력을 입력 `hidden_state`에 더한다
(`src/main.cpp:399`; 래퍼 `src/kernels.cu:319-329`, 커널 `:311-316`). 이 잔차
연결이 위 파이프라인에서 "residual"로 표시한 단계다. 그리고 post-attn
rmsNorm(`:401`)이 잔차를 정규화해 MLP로 넘긴다.

## SwiGLU MLP

MLP는 게이트 활성화(SwiGLU)를 쓰는 세 단계 투영이다. gate와 up 두 투영을
만든 뒤, 게이트에 SiLU 활성화를 적용하고 up과 요소별로 곱해 down 투영으로
축소한다. 레이어별 `mlp_gate_proj`/`mlp_up_proj`/`mlp_down_proj` 가중치가
2장에서 배정되어 있다(`src/main.cpp:132-145`).

- **gate GEMM** — `src/main.cpp:414-432`. `m=HIDDEN_DIM`(8192)으로 투영한다.
- **up GEMM** — `src/main.cpp:435-453`. 같은 크기로 투영한다.
- **silu** — `src/main.cpp:459`. gate를 in-place로 `SiLU(gate)*up`로 덮어쓴다
  (래퍼 `src/kernels.cu:341-344`, 커널 `:331-338`).
- **down GEMM** — `src/main.cpp:470-489`. 입력은 silu 결과가 덮어쓴 gate
  버퍼이고, 출력은 `buf_2048_2`(o_proj와 공유)다.
- **residualAdd** — `src/main.cpp:492`. MLP 출력을 입력 `hidden_state`에
  더한다.

`evidence/trace.md:118-121`이 이 다섯 단계와 버퍼 공유를 정리한다. MLP가
레이어 루프의 마지막 단계이며, 잔차가 합쳐진 `hidden_state`가 다음 레이어의
입력 rmsNorm으로 들어간다.

## 최종 rmsNorm과 로짓 GEMM

레이어 루프가 끝나면 최종 rmsNorm(`src/main.cpp:494`, 가중치 `norm`)이
`hidden_state`를 정규화하고, 로짓 GEMM이 어휘 전체에 대한 점수를 만든다.
로짓 GEMM은 임베딩 테이블 `embed_tokens`를 전치 대상으로 쓰는, Q 투영과 같은
전치 트릭이다. `m=VOCAB_SIZE, n=prompt_len, k=EMBEDDING_LENGTH`에
`embed_tokens`를 전치해 곱한다(`src/main.cpp:509-527`, `evidence/claims.md:24`).
결과를 행-주로 읽으면 토큰마다 (VOCAB_SIZE,) 로짓 벡터가 `prompt_len`줄
깔린다.

이후는 3장에서 읽은 출구다. 로짓을 CPU로 복사하고(`:529`), 마지막 토큰 행에서
CPU argmax로 첫 토큰을 고른 뒤(`:533-543`) 상태를 갱신한다(`:546-548`). 로짓
GEMM이 `embed_tokens`를 전치해서 쓰는 것은, 3장에서 본 "출구의 전치 대상"이
바로 이 호출이라는 뜻이다.

## 검증 경로

이 장이 인용한 rmsNorm·RoPE·GEMM·silu에는 대응하는 단위 테스트가 없다.
인벤토리에서 유일한 테스트는 `tests/test_softmax.cu` 하나뿐이다
(`evidence/recon.md:12`). 특히 전치 트릭의 수치 정확성은 테스트로 확인되지
않았고, Claim 2가 이를 한계로 못 박는다(`evidence/claims.md:24`). RMSNorm·GEMM·
attention 커널의 정확성이 테스트로 뒷받침되지 않는다는 점도 정찰 메모가
기록한다(`evidence/recon.md:38`). 이 장은 이 연산들의 수치 정확성을 주장하지
않는다.

## 이 장에서 다루지 않는 것

- attention 스코어·causalMask·softmax의 계산 상세, KV 캐시 산포 — 5장.
- paged attention 커널 — 10장.
- decode 루프의 배치 GEMM(`n=num_active_slots`) — 6~8장.
- README의 성능 수치·설계 주장 — 시리즈 범위 밖(`guide.md:7-9`).
- rmsNorm·RoPE·silu 커널 내부의 스레드 단위 세부 분해 — 이 시리즈의 근거가
  래퍼와 커널의 줄 범위만 기록한다.

## 한계

  `tests/test_softmax.cu` 하나뿐이다(`evidence/claims.md:24`,

  17토큰 이하여서 도달하지 않지만, 일반 prefill 경로의 한계로 남는다
  (`evidence/claims.md:35`).
- GQA 비율(4)과 헤드 수가 상수로 박혀 있어(`src/main.cpp:20-24`) 모델 구조가

  않는다. 위 "검증 경로"와 같은 이유다.

## 정리

4장은 3장이 비워 둔 레이어 가운데를 채웠다. prefill의 레이어 루프(`src/main.cpp:
164-492`)는 16개 레이어 각각에 대해 입력 rmsNorm(`:166`) → Q/K/V 투영
(`:177-240`) → rope(`:244-245`) → KV 산포(`:247-288`, 5장) → attention
(`:301-371`, 5장) → o_proj(`:377-396`) → residual(`:399`) → post-attn
rmsNorm(`:401`) → SwiGLU MLP(`:414-492`) 순서를 따른다. 모든 GEMM은 행-주
메모리를 열-주로 해석하는 cuBLAS 전치 트릭(`CUBLAS_OP_T/CUBLAS_OP_N`)으로
걸리며, 결과를 다시 전치하지 않아도 된다(Claim 2). GQA는 4개 Q 헤드가 1개
K/V 헤드를 공유한다(Claim 7).

이 장의 요점은 "레이어는 정규화·투영·위치 회전으로 입력을 만들고, attention을
지나 잔차와 MLP로 변형한다"는 순서의 골격과, 그 모든 GEMM이 한 가지 cuBLAS
호출 관용구로 통일된다는 사실이다. 다음 장은 이 장이 순서만 남긴 attention과
KV 캐시 산포를 펼친다.

# 2. 가중치 적재와 GPU 버퍼 설계

이 글의 모든 경로와 줄 번호는 고정 revision
`e25bf1994efa90bc98b721ba7c527402f86fbeaf` 의 트리를 가리킨다. 표기는
`파일:시작-끝` 형식이며, 실행 결과가 아니라 소스 인용이다.

## 이 장의 질문

safetensors 가중치를 어떻게 읽어 GPU 메모리에 올리고, 어떤 버퍼를 미리 잡아
두는가. 코드 범위는 `src/main.cpp` 하나다. 이 장의 최소 근거는 코드 인용 3건,
테스트 0건, 실행 0건이다. 테스트가 없으므로 모든 검증은 소스 인용으로만
이뤄진다.

이 장은 버퍼 크기 산정과 별칭(aliasing) 설계를 소유한다. 빌드 경계와 실행
진입점은 1편이, prefill 의 커널 호출 순서와 병렬 리덕션은 3편이, cuBLAS 의
전치·레이아웃은 4편이, decode 계열 커널과 paged attention 은 5·6편이, 슬롯·큐의
수명주기는 7편이 맡는다. GPU 와 CUDA 툴체인이 없는 환경이라 어떤 할당·복사도
실행하지 않았다. 가중치 파일 `model.safetensors` 는 gated 모델
`meta-llama/Llama-3.2-1B-Instruct` 의 것이라 확보도 제약이다.

## 진입 순서에서 이 장의 위치

`main` 은 cuBLAS 핸들을 만들고(`src/main.cpp:557-563`) 곧바로 `loadWeights` 를
호출한다(`src/main.cpp:566-569`). 이어 RoPE 주파수 테이블을 초기화하고
(`src/main.cpp:572`), paged KV cache 할당자를 세운 뒤(`src/main.cpp:574-581`),
프롬프트 큐(`src/main.cpp:583-594`)와 슬롯·배치 상태(`src/main.cpp:597-610`)를
준비하고, 마지막으로 연산 버퍼를 잡는다(`src/main.cpp:617-693`). 그 뒤 초기
prefill 루프가 빈 슬롯을 채운다(`src/main.cpp:695-708`).

이 장이 다루는 두 덩어리는 `loadWeights`(`src/main.cpp:79-147`)와 버퍼 할당
구간(`src/main.cpp:617-693`)이다. paged KV cache 와 슬롯 상태는 6·7편의
주제지만, 메모리 배치라는 관점에서 초기화 지점만 여기서 확인한다.

## safetensors 한 파일을 한 번에 올린다

`loadWeights` 는 네 단계로 나뉜다.

1. GPU 확인. `checkGPUStatus`(`src/main.cpp:40-62`)를 먼저 호출하고
   (`src/main.cpp:81-84`), 장치가 하나도 없으면 오류를 출력한 뒤 `return 1`
   한다(`src/main.cpp:44-48`).
2. 파일 열기. 작업 디렉터리의 `model.safetensors` 를 이진 모드로 연다
   (`src/main.cpp:87`). 실패하면 `return 1` 이다(`src/main.cpp:88-93`).
3. 헤더 읽기. 앞 8바이트에서 헤더 길이를 읽고(`src/main.cpp:96-97`), 그
   길이만큼 헤더 문자열을 읽는다(`src/main.cpp:99-101`).
4. 오프셋 산정. 헤더 JSON 을 파싱한 뒤(`src/main.cpp:104`) 각 텐서를 순회하며
   `__metadata__` 를 건너뛰고(`src/main.cpp:106-111`), `data_offsets` 의
   끝값으로 `max_offset` 을 갱신하고 시작값을 이름→오프셋 맵에 기록한다
   (`src/main.cpp:112-117`).

이 `max_offset` 이 가중치 전체의 바이트 크기다. 코드는 이 크기로 한 번만
`cudaMalloc` 하고(`src/main.cpp:120-121`), 같은 크기의 CPU 벡터를 만들어 파일
나머지를 읽은 뒤(`src/main.cpp:123-125`), 한 번의 H2D 복사로 GPU 에 올린다
(`src/main.cpp:127`). 텐서별로 나눠 잡는 것이 아니라 단일 할당이며, 개별
텐서는 그 안의 주소 범위다.

마지막으로 텐서 이름→오프셋 맵으로 `Weights` 구조체의 포인터를 채운다
(`src/main.cpp:132-145`). 구조체(`src/main.cpp:64-77`)는 `embed_tokens`
(`src/main.cpp:66`)와 `norm`(`src/main.cpp:76`) 두 단일 포인터, 그리고 레이어별
배열 9종(`src/main.cpp:67-75`)을 담는다. 레이어별 배열은 `input_layernorm`,
`mlp_gate_proj`, `mlp_up_proj`, `mlp_down_proj`, `post_attn_layernorms`, `w_k`,
`w_o`, `w_q`, `w_v` 이고, 각각 `N_LAYERS`(16)개의 포인터를 가진다
(`src/main.cpp:15`, `src/main.cpp:67-75`). 따라서 필드는 모두 11개다. 매핑
루프는 16개 레이어를 돌며 9종 텐서의 주소를 계산한다(`src/main.cpp:134-145`).

구조체 주석은 모델 구조가 항상 Llama 3.2 1B-Instruct 라고 가정한다고 밝히고
(`src/main.cpp:130-131`), 경로 역시 인자가 아니라 문자열로 박혀 있다
(`src/main.cpp:87`).

## 미리 잡아 두는 버퍼 16개

버퍼 할당은 `src/main.cpp:617-693` 에 모여 있다. 크기 상수는
`src/main.cpp:12-38` 에 있다. `MAX_BUFFER_SIZE` 는
`max(MAX_PROMPT_LEN, BATCH_SIZE)` 이고(`src/main.cpp:31`), 512 와 2 중 큰
값이므로 512 다. bf16 원소는 2바이트다.

아래 표는 이 구간에서 `cudaMalloc` 또는 호스트 벡터로 미리 잡는 버퍼를
정리한다.

## 크기 산술

표의 바이트는 상수에서 직접 계산한 값이다. `prefill_attn_scores` 는
`512 × 512 × 32 = 8,388,608` 원소이고, bf16 이므로 `16,777,216` 바이트, 즉
16 MiB 다(`src/main.cpp:30`, `src/main.cpp:20`, `src/main.cpp:647-648`).
`gate` 와 `up` 은 각각 `512 × 8192 = 4,194,304` 원소로 8 MiB 다
(`src/main.cpp:17`, `src/main.cpp:662-663`, `src/main.cpp:667-668`).
`embed_proj` 는 `512 × 128,256 = 65,667,072` 원소로 125.25 MiB 다
(`src/main.cpp:25`, `src/main.cpp:676-677`).

`embed_proj` 의 원소 수는 `prefill_attn_scores` 의 약 7.8배다
(`65,667,072 ÷ 8,388,608 ≈ 7.83`). 로짓 버퍼가 이 장에서 가장 큰 단일
버퍼이고, 그 호스트 사본 `embed_proj_cpu` 도 같은 원소 수로 잡힌다
(`src/main.cpp:681-682`). `embed_proj` 는 `MAX_BUFFER_SIZE`(512)를 쓰므로
배치 크기 2가 아니라 최대 프롬프트 길이가 크기를 지배한다
(`src/main.cpp:31`).

임시 버퍼는 더 작다. `k_proj_temp_buf`·`v_proj_temp_buf` 는
`512 × 512 = 262,144` 원소(512 KiB)이고(`src/main.cpp:635-639`), decode 용
`k_proj_batched_buffer`·`v_proj_batched_buffer` 는 `2 × 512 = 1024` 원소
(2 KiB)다(`src/main.cpp:689-693`). `gpu_input_tokens` 는 `512 × 4 = 2048`
바이트다(`src/main.cpp:617-618`).

## 버퍼 별칭 설계

두 버퍼는 서로 다른 두 역할이 시간차를 두고 공유한다. 코드 주석이 이를
명시한다.

- `buf_2048_1` 은 `q_proj` 와 `attn_scores_v` 가 공유한다
  (`src/main.cpp:628`). 먼저 `q_proj = buf_2048_1` 로 Q 투영 출력을 받고
  (`src/main.cpp:177`), 헤드별 어텐션 점수 계산이 이 `q_proj` 를 Q 입력으로
  읽는다(`src/main.cpp:301-327`, 특히 `src/main.cpp:304`). Q 를 다 읽은
  뒤에야 `attn_scores_v = buf_2048_1` 로 같은 버퍼를 점수×V 출력에 다시 쓴다
  (`src/main.cpp:343`).
- `buf_2048_2` 는 `o_proj` 와 `down` 이 공유한다(`src/main.cpp:656`).
  `o_proj = buf_2048_2` 로 O 투영 출력을 받고(`src/main.cpp:377`), 잔차
  커널이 이를 읽어 `hidden_state` 에 더한 뒤(`src/main.cpp:399`),
  `down = buf_2048_2` 로 down 투영 출력을 받는다(`src/main.cpp:470`).

두 경우 모두 같은 시점에 한 역할만 쓴다. Q 와 점수×V 출력, O 와 down 출력이
동시에 살아 있을 필요가 없으므로 하나의 버퍼로 충분하다. 다만 이 안전성은
소스상의 소비 순서에 근거한 정적 주장이며 실행 검증은 없다.

decode 경로에서는 `pagedAttention` 의 출력이 다시 `buf_2048_1` 에 쓰인다
(`src/main.cpp:878`). 그 in-place 안전성과 paged attention 의 입출력은 6편이
소유한다.

## paged KV cache 와 슬롯 상태의 초기 배치

버퍼 16개와 별개로, `main` 은 paged attention 용 메모리도 미리 잡는다.
`kv_cache` 를 2GB 로 `cudaMalloc` 하고(`src/main.cpp:575-576`, 상수
`src/main.cpp:35`), `free_blocks` 를 0 부터 65535 까지 채운다
(`src/main.cpp:577-578`, `src/main.cpp:37`). `block_table` 은
`MAX_SEQUENCES × N_LAYERS × MAX_BLOCKS_PER_SEQ` 개를 전부 `-1` 로
초기화하고(`src/main.cpp:579`), 같은 크기의 `block_table_gpu` 를 `cudaMalloc`
으로 할당한다(`src/main.cpp:580-581`). 이 시점에는 GPU 로의 업로드가 없다.
실제 H2D 복사는 `prefill` 이 끝날 때 `block_table` 전체를 대상으로 일어난다
(`src/main.cpp:552`).

슬롯·배치 상태도 이때 잡힌다. `is_slot_free` 는 `BATCH_SIZE` 개를 `true` 로
두고(`src/main.cpp:597`), `generated_tokens`·`last_generated_tokens`·
`current_prompt_len` 을 만든다(`src/main.cpp:599-601`). 커널에 연속 메모리로
넘길 `active_slots`·`active_tokens` 는 빈 벡터로 두고(`src/main.cpp:604-605`),
`gpu_active_slots`·`gpu_seq_lens` 를 각각 `BATCH_SIZE` 크기로 `cudaMalloc`
한다(`src/main.cpp:607-610`). 이 상태들의 수명주기는 7편이 소유한다.

## 이 장이 다루지 않는 것

- 빌드 경계와 실행 진입점: 1편. `full_test.sh` → `test.sh` → `build.sh` →
  `run.sh` 경로와 이중 백엔드 분기는 여기서 다루지 않는다.
- prefill 의 커널 호출 순서와 병렬 리덕션: 3편.
- cuBLAS 의 전치 플래그와 열-행 우선 레이아웃: 4편. 이 장은 버퍼 크기와
  별칭만 다룬다.
- decode 계열 커널 변형: 5편.
- `pagedAttentionKernel` 의 block table 인덱싱과 in-place 쓰기: 6편.
- 슬롯·큐의 수명주기와 종료 조건: 7편.
- 실제 `model.safetensors` 적재 실행과 수치 검증: 이 장은 실행하지 않는다.

## 이 장의 한계

- 이 시리즈는 NVIDIA GPU 와 CUDA 툴체인이 없는 환경에서 작성되어 어떤
  할당·복사·커널도 실행하지 않았다. `loadWeights` 와 버퍼 크기 주장은 모두
  소스 인용이다.
- 이 장의 최소 근거는 코드 인용 3건, 테스트 0건, 실행 0건이다. 커널 실행
  시간·처리량·메모리 사용량은 측정하지 않으며, 이 장에는 측정값으로 읽힐 수
  있는 성능 수치가 없다. 표의 바이트는 컴파일 타임 상수에서 계산한 산정값이지
  측정값이 아니다.
- 가중치 파일은 gated 모델 `meta-llama/Llama-3.2-1B-Instruct` 의
  `model.safetensors` 라서 확보가 제약이고, 실제 적재는 검증되지 않았다.
- `loadWeights` 는 모델 구조가 항상 Llama 3.2 1B-Instruct 라고 가정하고
  (`src/main.cpp:130-131`) 파일 경로도 하드코딩돼 있다(`src/main.cpp:87`).
  다른 모델에서는 텐서 이름 매핑이 깨진다.
- 버퍼 별칭의 안전성은 소비 순서에 대한 정적 주장이며, 동시성·경합의 실행
  검증은 없다.
- `MAX_SEQ_LEN`, `BATCH_SIZE`, `MAX_PROMPT_LEN` 등은 TODO 주석이 붙은
  하드코딩 상수다(`src/main.cpp:28-31`). 이 값이 바뀌면 표의 크기가 함께
  바뀐다.

## Why online softmax

An ordinary softmax first computes the maximum over the whole score row, exponentiates each
element against that maximum, and then divides by the sum. This approach either sweeps the
row twice or has to materialize the row in memory to run a reduction. Decode's paged
attention goes differently. It walks the tokens one at a time, **updating the running
maximum and the exponential sum of the tokens seen so far**, and when the maximum changes,
it rescales the accumulated values to the new baseline. This is the FlashAttention-family
online softmax. The kernel quotes this definition directly in a source comment
(`src/kernels.cu:473`).

The kernel starts with three pieces of state (`src/kernels.cu:474-476`).

| State | Initial value | Meaning |
|---|---|---|
| `current_max` | `-INFINITY` (`:474`) | Running maximum of the scores seen so far |
| `acc` | `0.0f` (`:475`) | Accumulated exponential-weighted V before normalization |
| `d` | `0.0f` (`:476`) | The denominator, i.e. the exponential sum |

The comment explains `d` as "denominator, same name as in paper above" (`:476`). That `acc`
is the weighted sum and the final output is `acc/d` is confirmed directly by the update rule
(`:518-519`) and the output (`:522`). There is no array holding a score row anywhere. Each
thread carries only these three scalars through the token loop (`:478-482`).

## The update rule that accumulates with three scalars

Once the dot product for one token is determined, the update happens in the following order
(`src/kernels.cu:510-519`).

```
new_max = current_max
if (dot_product > current_max) new_max = dot_product   (:510-514)
correction_factor = expf(current_max - new_max)        (:515)
current_max = new_max                                  (:516)
exp_score = expf(dot_product - current_max)            (:517)
d   = d   * correction_factor + exp_score              (:518)
acc = acc * correction_factor + exp_score * v          (:519)

... after iterating all tokens
output = acc / d                                       (:522)
```

The heart of this update is `correction_factor` (`:515`). When a new maximum appears, the
`d` and `acc` accumulated so far against the old `current_max` are misaligned in baseline.
Multiplying by `cf = exp(old_max - new_max)` rescales the previous accumulation to the new
maximum's baseline (`:518-519`), and then adds the new score's contribution. This yields the
exact softmax denominator and weighted sum in a single pass, without knowing the maximum in
advance.

One point to note is that this update is **the result of iterating over all tokens of one
kernel invocation within that invocation**. The state is not carried over between decode
iterations and accumulated incrementally. Each time the kernel is called,
`current_max`/`acc`/`d` restart from their initial values (`:474-476`) and it traverses up to
`num_blocks` again (`:478-482`). Every decode step recomputes from scratch as much as its
own sequence length.

## Computing the dot product with a warp tree sum

The scores fed into the online softmax are dot products of Q and K. The kernel does not
assign this dot product to a single thread; it divides the computation across a warp.
`pagedAttentionKernel` runs a block with `HEAD_DIM=64` (`src/kernels.cu:525-527`; `HEAD_DIM`
definition `:11`), so there are 64 threads in one block. Each thread owns one dimension of Q
(`:469`).

```
thread_id 0..63, each one dimension of Q:
  q = q_proj[active_slot*2048 + q_head_id*64 + thread_id]   (:469)
  k = kv_cache[... + thread_id]                             (:484)
  qk = (float)q * (float)*k                                 (:486)

warp 0 (thread 0..31):  qk += __shfl_down_sync(mask, qk, 16)  (:489)
                        qk += __shfl_down_sync(mask, qk, 8)   (:490)
                        qk += __shfl_down_sync(mask, qk, 4)   (:491)
                        qk += __shfl_down_sync(mask, qk, 2)   (:492)
                        qk += __shfl_down_sync(mask, qk, 1)   (:493)
  → thread 0 holds the sum of warp 0's 32 lanes
warp 1 (thread 32..63): the same tree sum
  → thread 32 holds the sum of warp 1's 32 lanes

thread 0  → dot_products[0] = qk    (:494-497)
thread 32 → dot_products[1] = qk    (:498-501)
__syncthreads()                      (:502)
thread 0: dot_products[0] = (dot_products[0] + dot_products[1]) / SQRT_HEAD_DIM  (:503-506)
__syncthreads()                      (:507)
all threads: dot_product = dot_products[0]  (:508)
```

The `__shfl_down_sync` offsets 16·8·4·2·1 are the standard tree sum on a 32-thread warp
(`:489-493`). Since a block has two warps, the two halves' partial sums are collected into a
shared array `dot_products[2]` (`:463`), and thread 0 adds the two and divides by
`SQRT_HEAD_DIM` (`:503-506`). This scale corresponds to attention's `1/sqrt(head_dim)`.
`SQRT_HEAD_DIM=8` (`src/kernels.cu:12`) and `HEAD_DIM=64`, so `1/8 = 1/sqrt(64)`. This
matches prefill setting the same scale as `attn_alpha = 1.0f / 8.0f` (`src/main.cpp:649`)
and the prefill score GEMM comment writing `Q*K^T/sqrt(64)` (`src/main.cpp:298`).

The mask `WARP_FULL_MASK` passed to `__shfl_down_sync` is defined by the portability header.
It splits into a 64-bit mask (`0xffffffffffffffffULL`, `src/cuda_to_hip.h:50`) on the HIP
path and a 32-bit mask (`0xffffffff`, `:59`) on the CUDA path.

## The difference between prefill `softmax` and decode online softmax

Prefill's separate `softmax` is also an online softmax using the rescale at `:281`
(`evidence/trace.md:112-113`). Prefill does a parallel tree reduction over the global score
row, whereas decode streams tokens with scalar state and no score row. Only this high-level
contrast is covered here; the details of prefill are in the scope of Chapters 4 and 5.

## Where this kernel is called

The online softmax is not a standalone function but lives inside `pagedAttentionKernel`. The
decode layer loop goes through KV scatter (`src/main.cpp:851-873`) → `block_table_gpu` H2D
re-synchronization (`:876`) → `pagedAttention` call (`:878`), and the call wrapper launches
the kernel with grid `(num_active_slots, NUM_Q_HEADS)` and block `HEAD_DIM=64`
(`src/kernels.cu:525-527`). In the kernel body, after the slot/head mapping (`:464-469`) and
the physical block lookup (`:480`), the above dot product and online softmax execute inside
the token loop (`:482`).

One point to flag is that this kernel **reads only the K/V tokens already written to the
cache**. The physical block traversal range is set to `num_blocks = (seq_len + BLOCK_SIZE -
1) / BLOCK_SIZE` (`:471`), and within a block it traverses only `tokens_in_block = min(seq_len
- logical_block_idx*BLOCK_SIZE, BLOCK_SIZE)` (`:481-482`). So masking is implemented as "not
reading the not-yet-written future tokens," without a separate causal-masking kernel or
`-INFINITY` masking (`evidence/claims.md:88`).

## Limitations

- **Claim 8's `dot_products[2]` assumption** — The current `HEAD_DIM=64` launch creates
  exactly two full warps (`src/kernels.cu:525-527`). The `dot_products[2]` and
  `WARP_FULL_MASK` reduction structure (`:463`, `:489-507`) is hard-wired to this
  configuration, so changing `HEAD_DIM` requires revisiting the reduction structure and
  recompiling.
- **`softmaxDecode` is never called** — `softmaxDecode` and its kernel
  (`src/kernels.cu:408-458`) are defined but not called from `src/main.cpp`. Decode's
  softmax is handled by the online softmax inside `pagedAttentionKernel`, so this function
  appears to be unused (dead code) at this commit (`evidence/trace.md:216-219`).
- **Numeric accuracy unverified** — The numeric accuracy of the online update and the warp
  tree sum is not confirmed by tests within the ranges cited in this chapter. The only
  kernel test is `tests/test_softmax.cu`, and the repository was not run
  (`evidence/recon.md:4`, `:12`).
- **No performance claims** — Whether online softmax saves memory or how long it takes to
  run has no evidence base in Claims 1–10, so neither is written.

## Summary

This chapter read how decode's `pagedAttention` turns attention scores into probabilities.
`pagedAttentionKernel` does not store a score row; it carries only the three scalars
`current_max`/`acc`/`d` through the tokens, and when a new maximum appears it rescales the
previous accumulation with `cf = exp(old_max-new_max)` and then adds the contribution
(`src/kernels.cu:474-476`, `:510-519`). At the end it outputs `acc/d` (`:522`). The score's
dot product is obtained by each thread taking one dimension of Q and a `__shfl_down_sync`
tree sum (`:489-493`), then combining the two warp halves via `dot_products[2]` and dividing
by `SQRT_HEAD_DIM` (`:494-508`).

Prefill does a parallel tree reduction over the global score row, whereas decode streams
tokens with scalar state and no score row. The next chapter reads the other half of
`pagedAttentionKernel` that contains this online softmax — namely, the structure that
traverses physical blocks along the block table.

# ko-01 리뷰 — 제품 경계와 실행 진입점

고정 revision `e25bf1994efa90bc98b721ba7c527402f86fbeaf` 의 체크아웃 트리
(`CMakeLists.txt`, `build.sh`, `run.sh`, `test.sh`, `full_test.sh`,
`src/cuda_to_hip.h`, `src/kernels.cuh`, `include/json.hpp`, `src/main.cpp`,
`src/kernels.cu`)와 첨부 증거(`guide.md`, `series.yaml`, `briefs.md`,
`evidence/claims.md`, `evidence/trace.md`, `evidence/recon.md`)를 기준으로
`articles/ko-01.md` 의 모든 기술 주장·인용·범위·시각 자료·성능 서술을 대조했다.
초안이 인용한 CMakeLists·shim·셸 스크립트·헤더의 줄 번호는 `claims.md` 가
"첨부에 없다"고 밝힌 파일들이지만, 고정 revision 스냅샷의 실제 본문과 전부
일치함을 직접 확인했다(Claim 1·2 의 Medium 한계가 이 장의 서술에서는 해소된다).

## Decision

**PASS**

`add_executable` 의 두 번역 단위, `USE_HIP` 이중 백엔드 분기, `cuda_to_hip.h`
shim, 네 셸 스크립트의 대표 실행 경로, `main` 초기화 순서, 하드코딩 프롬프트와
표준 입력 무시, 커널 11개 분류, 시각 자료 두 개의 필수 주장까지 전부 실제 소스와
첨부 증거에 정확히 일치한다. 측정값으로 읽힐 성능 수치는 없고, 범위·용어 소유·
한계 서술도 guide 의 결정과 어긋나지 않는다. 수정을 요구하는 오류는 찾지
못했다. 아래 관찰은 모두 비차단이며 게시 조건을 위반하지 않는다.

## Verified claims

  고정 revision 해시(`guide.md:6`)와 `파일:시작-끝` 표기도 맞다.
- **제품 번역 단위.** `add_executable(tiny-vllm src/main.cpp src/kernels.cu)`
  (`CMakeLists.txt:49-52`)와 include 경로 `src`·`include`
  (`CMakeLists.txt:62-63`)가 실제 파일과 일치한다. `src/main.cpp:4`·`7`·`8` 이

- **표의 필수 주장.** `product-translation-units` 표가 두 요소 — 두 번역 단위로만
  빌드(`CMakeLists.txt:49-52`, `src/main.cpp:555-1044`,

  `src/main.cpp:7`) — 를 모두 답한다. `include/json.hpp` 의 버전·라이선스

- **이중 백엔드 분기 전부.** `option(USE_HIP ... OFF)`(`CMakeLists.txt:3`),
  언어 분기 `13`/`15`, nvcc 경로 `5-8`, CUDA 표준·아키텍처 `21-25`, 백엔드별
  플래그 `32-38`, 의존 패키지 `42-44`/`46`, HIP 번역 단위 `54-60`, 링크

## Problems

수정이 필요한 오류는 없다. 아래는 정밀도·일관성 관찰이다.

- **O1 (선택, 인용 정밀도).** 32행의 `main`(`src/main.cpp:555-556`)은 시그니처와
  여는 중괄호만 가리킨다. 같은 문장이 본문을 `555-1044` 로 적으므로 혼동은 없으나
  `555-1044` 로 통일하면 더 정확하다.
- **O2 (선택, 범위 정밀도).** 151-152행의 초기 prefill 루프 `695-708` 은
  `trace.md:75` 와 동일하지만, 실제 `for` 블록은 `695-707` 이고 `708` 은 빈
  줄이다. 근거와 일치하므로 오류는 아니나 `695-707` 로 좁히면 정확하다.
- **O3 (선택, 시각 자료).** mermaid 는 `hip_bf16.h`/`cuda_bf16.h` 노드와
  "동일 소스의 cuda* · cublas* 이름" 노드로 shim 을 표현하지만
  `__nv_bfloat16`→`__hip_bfloat16` 매핑을 명시적으로 드러내지는 않는다.
  같은 절 본문(93-94행)이 bfloat16 흡수를 설명하므로 계약은 충족되나, 타입 매핑
  노드를 하나 추가하면 `dual-backend-branch` 의 두 번째 필수 요소가 그림만으로
  더 분명해진다.
- **O4 (선택, 표현).** 49행 "컴파일되는 번역 단위가 아니므로 제품 규모에서
  제외한다"는 문장은 `json.hpp` 가 `main.cpp` 번역 단위에 포함되어 컴파일된다는
  사실과 느슨하게 읽힐 수 있다. 제외 사유는 제3자 vendored 헤더라는 점(결정 002,
  `guide.md:48`)이므로 "번역 단위가 아니고 제3자이므로 규모 산정에서 제외한다"로
  다듬으면 오해가 없다.
- **O5 (참고, 근거 문서 불일치).** `dual-backend-branch` 의 형식을
  `guide.md:173`·`briefs.md:39` 는 "블록 다이어그램", `series.yaml:27` 은
  `mermaid` 로 적는다. 초안은 `series.yaml` 에 맞춰 mermaid 로 썼으므로 초안
  결함은 아니지만, 게시 전에 두 근거 문서의 형식 표기를 일치시킬 것을 남긴다.
- **O6 (참고, 범위).** `src/kernels.cuh:3-9` 인용은 code_scopes 밖이지만
  이중 백엔드 별칭 중복을 보이는 정확한 인용이고 3편·6편 소유 주제를 침범하지
  않으므로 그대로 두어도 무방하다.

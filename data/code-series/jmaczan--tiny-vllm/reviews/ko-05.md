# ko-05 리뷰 — 토큰 하나만 만드는 decode 경로

고정 revision `e25bf1994efa90bc98b721ba7c527402f86fbeaf` 의 체크아웃 트리
(`src/main.cpp`, `src/kernels.cu`, `src/kernels.cuh`, `python/decode_test.py`)와
첨부 증거(`guide.md`, `series.yaml`, `briefs.md`, `evidence/claims.md`,
`evidence/trace.md`, `evidence/recon.md`)를 기준으로 `articles/ko-05.md` 의 모든
기술 주장·인용·범위·소유권·성능 서술을 대조했다.

## Decision

**PASS**

decode 루프의 위치와 슬롯 재구성, decode 전용 커널 네 쌍, prefill 대비 인덱싱
차이, RoPE 현재 위치 회전·매 호출 재계산, K/V 배치·블록 분산, `pagedAttention`
대체, 미호출 `softmaxDecode`, 나머지 레이어·로짓·종료 분기까지 모든 기술 주장이
실제 소스와 첨부 증거에 정확히 일치한다. `prefill-decode-contrast` 표가
`series.yaml` 의 필수 주장을 답하고, 최소 근거 `code 4 / tests 1 / runtime 0` 을
충족하며, 측정값으로 읽힐 성능 수치는 없다. 수정을 요구하는 오류는 찾지 못했다.
아래 4건은 비차단 정밀도 관찰이며 게시 조건을 위반하지 않는다.

## Problems

수정이 필요한 오류는 없다. 아래는 정밀도·표현 관찰이다.

- **O1 (선택, 인용 정밀도).** 초안 194행은 "블록을 순회하며 점수를 계산하고
  (`src/kernels.cu:478-485`)"라고 쓴다. 478-485 는 블록 순회와 K/V 주소 계산
  까지이고, 실제 점수 곱 `float qk = (float)q * (float)*k;` 는 486행이다(이
  행은 다음 절의 `486-519` 인용에 포함된다). `478-486` 으로 넓히거나 "K/V
  주소를 계산하고"로 다듬으면 더 정확하다.
- **O2 (선택, 인용 귀속).** 초안 62행 "네 함수 모두 `src/kernels.cuh:23-28` 에
  선언되어 있다"에서 같은 절의 불릿은 `__global__` 커널과 래퍼를 함께 나열한다.
  `src/kernels.cuh:23-28` 이 선언하는 것은 래퍼 네 개
  (`embeddingGatherDecode`, `ropeDecode`, `softmaxDecode`, `pagedAttention`)이고
  `__global__` 커널은 헤더에 없다. "네 래퍼 함수 모두"로 다듬으면 모호함이 없다.
- **O3 (선택, 인용 귀속).** 초안 183-186행은 decode 의 `block_table` 전체 H2D
  (`src/main.cpp:876`)에 전체 복사 TODO(`src/main.cpp:551`)가 붙은 것처럼
  서술한다. 실제 TODO 는 prefill 의 H2D(`552`) 위에 있고, decode 의 복사는
  레이어 루프 안에서 매 레이어 일어난다(한계 절 258-259행이 "매 레이어마다"로
  정확히 밝힌다). TODO 가 prefill 자리의 것임을 문장에서 구분하면 좋다.
- **O4 (선택, 표기).** 초안 40행의 `current_prompt_len[slot] + 1` 은 실제
  `current_prompt_len[active_slot] + 1`(`src/main.cpp:755`, 여기서
  `active_slot = active_slots[slot]`)이다. 인덱스 표기를 소스와 맞추면 더
  정확하다.

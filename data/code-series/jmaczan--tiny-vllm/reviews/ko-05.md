# ko-05 리뷰: 토큰 하나만 만드는 decode 경로

## Decision

**REVISE**

기술 주장의 실질 내용은 고정 revision 트리의 실제 소스
(`src/main.cpp`, `src/kernels.cu`, `src/kernels.cuh`)와 첨부 근거(`claims.md`,
`trace.md`, `guide.md`, `briefs.md`, `series.yaml`)에 전부 정합한다. 인용 줄 번호도
`series.yaml`·`guide.md`·`trace.md`·`claims.md` 전반에 걸쳐 실제 파일과 일치한다.
다만 세 곳에서 인용 규율과 서술 정밀도의 문제가 있어 수정이 필요하다: (1)
"레이어 안에서 호출되는" 서술이 `embeddingGatherDecode`(레이어 루프 밖, 759행)와
어긋난다. (2) 초안 스스로 "첨부에 없다"고 한계로 밝힌 `src/kernels.cuh` 에 대해
구체 줄 번호(`:23-25`, `:25`)를 인용한다. (3) `python/decode_test.py` 의 기능
서술을 `recon.md:37-38` 로 인용하지만, 해당 줄은 크기·역할만 담고 기능 서술은
담지 않는다. 모두 미미한 수준이며 기술 오류는 아니다.

## Problems

1. **"레이어 안에서 호출되는" 서술이 `embeddingGatherDecode` 와 어긋난다.** 초안은
   "decode 루프의 **레이어 안에서** 호출되는 decode 계열 함수는
   `embeddingGatherDecode`(`src/main.cpp:759`), `ropeDecode`(`847-848`),
   `pagedAttention`(`878`)뿐이다"라고 쓴다. 그러나 `embeddingGatherDecode` 는
   759행으로 레이어 루프(`760-972`) **밖**, decode 반복당 한 번 호출된다. 레이어
   안에 있는 것은 `ropeDecode`·`pagedAttention` 둘뿐이다. 문장의 의도(softmaxDecode
   는 어디서도 호출되지 않는다는 열거)는 맞지만 "레이어 안에서"는 부정확하다.
2. **첨부에 없는 `src/kernels.cuh` 의 구체 줄 번호를 인용한다.** 본문이
   "`softmaxDecode` 는 `kernels.cuh` 에 선언돼 있고(`src/kernels.cuh:25`)",
   출처 절이 "`src/kernels.cuh:23-25` — decode 계열 함수 선언"으로 적는다. 그런데
   초안 자신의 한계 절은 "`src/kernels.cuh` 와 `src/cuda_to_hip.h` **본문은 첨부에
   없어** 함수 시그니처 수준의 대조만 가능했다(`trace.md:219-221`)"라고 밝힌다.
   첨부 여섯 파일(`claims.md:3-4`)에 `kernels.cuh` 는 없다. 줄 번호는 고정 revision
   트리의 실제 파일과 일치하나(23-25행이 decode 계열 선언, 25행이 `softmaxDecode`),
   "첨부만 근거"라는 이 시리즈의 인용 규율과 내부 모순이다. 근거가 어디서 왔는지
   (스냅샷 대조)를 밝히거나 줄 번호를 빼야 한다.
3. **`decode_test.py` 기능 서술의 인용이 실제 출처와 어긋난다.** "Llama-3.2
   토크나이저로 채팅 템플릿 프롬프트 4개의 토큰 ID 열을 다시 텍스트로 디코드해
   매핑을 확인하는 12줄 스크립트"를 `recon.md:37-38` 로 인용하지만, 해당 줄은
   파일 크기(434B / 12줄)와 role(`test`)만 담는다. 기능 서술은 `recon.md` 에 없다.
   실제 파일(스냅샷)과는 일치하므로 기술 오류는 아니지만, 인용 소스가 내용을
   뒷받침하지 않는다. code_scopes 안의 파일이므로 파일 permalink 인용 또는 실제
   줄 인용으로 바꿔야 tests=1 의 근거도 견고해진다.

## Required fixes

1. "레이어 안에서 호출되는"을 "decode 경로에서 호출되는" 등으로 고쳐
   `embeddingGatherDecode`(레이어 루프 밖, `src/main.cpp:759`)를 포함하는 서술을
   정확히 한다. 레이어 루프 안(`760-972`)으로 한정할 경우
   `embeddingGatherDecode` 를 제외하고 `ropeDecode`·`pagedAttention` 둘만 남긴다.
2. `src/kernels.cuh:25`·`:23-25` 인용을 첨부 근거 규율에 맞춘다. 첨부에 없는
   파일의 구체 줄 번호를 쓰려면 "고정 revision 트리에서 함수 시그니처를 대조해
   확인했다"고 한계 절과 맞물려 명시하거나, 줄 번호 없이 "`kernels.cuh` 에
   선언돼 있다"까지만 쓰고 구현·호출부는 첨부 범위(`kernels.cu:442-458`,
   `main.cpp` decode 루프)로 뒷받침한다.
3. `decode_test.py` 기능 서술의 출처를 실제 파일로 바꾼다. `recon.md:37-38` 은
   "12줄"과 role 만 뒷받침하므로 유지하되, 기능 서술은
   `python/decode_test.py` permalink 인용(또는 핵심 줄 `t.decode(tokens)` 인용)으로
   교체한다. 이로써 `required_evidence.tests: 1` 근거가 인용 기반으로 완결된다.

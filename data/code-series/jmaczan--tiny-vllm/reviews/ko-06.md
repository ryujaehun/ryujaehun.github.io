## Verified claims

고정 revision 소스와 정확히 일치함을 확인했다.

- **블록 상수와 레이아웃.** `main.cpp:32-37` 인용이 문자 단위로 일치하고
  (`BLOCK_SIZE=16`, `V_OFFSET`, `BLOCK_BYTES`, `KV_CACHE_SIZE_BYTES`,
  `MAX_BLOCKS_PER_SEQ=128`, `NUM_BLOCKS`), `V_OFFSET = 16×512×2 = 16384` 바이트,
  `BLOCK_BYTES = 32768`, `2GB/32768 = 65536` 산술이 맞다. `kernels.cu:16-19` 의
  상수 중복과 `kernels.cu:6` 의 TODO("share these between main.cpp and kernels.cu")
  도 소스로 확인했다. `KV_DIM = 8×64`(K/V 헤드 8, 헤드 차원 64) 해석도 맞다.
- **block table 준비와 크기.** `main.cpp:575-581` 인용이 1:1 로 일치한다.
  `free_blocks` 는 `iota(0..NUM_BLOCKS-1)`, `block_table` 은 `-1` 초기화. 상수
  `main.cpp:15,29,36,38`(`N_LAYERS=16`, `BATCH_SIZE=2`, `MAX_BLOCKS_PER_SEQ=128`,
  `MAX_SEQUENCES=BATCH_SIZE`)을 채워 2×16×128=4096 항목이라는 산술도 맞다.
- **세 차원 인덱스의 네 등장 지점.** `slot·N_LAYERS·MAX_BLOCKS_PER_SEQ +
  layer·MAX_BLOCKS_PER_SEQ + block_idx` 가 prefill(`main.cpp:265`), decode
  (`main.cpp:858`), 어텐션 커널(`kernels.cu:480`), 슬롯 반납(`main.cpp:1022`) 네 곳에
  같은 모양으로 있음을 소스로 확인했다. "레이어마다 각자 다른 블록"이라는 이유와
  "같은 물리 번호라도 슬롯·레이어로 구분"이라는 해석도 인덱싱과 맞다.
- **커널 시그니처·병렬화·네 상태.** `kernels.cu:461` 인용이 문자 단위로 일치하고,
  본문 `464-469`(세 인덱스: `blockIdx.x` 활성 슬롯, `blockIdx.y` Q 헤드,
  `threadIdx.x` 64차원)도 정확하다. 런치 `<<<dim3(num_active_slots, NUM_Q_HEADS),
  HEAD_DIM>>>`(`527`)와 "`num_active_slots` 가 커널 본문에서 참조되지 않는다"는
  관찰, `kv_head_idx = q_head_id / 4` GQA 해석(`KV_DIM = 8×64`)이 모두 소스로
  뒷받침된다. "decode 계열에서 이 네 상태를 함께 받는 유일한 커널"이라는 주장은
  `guide.md:107-110`·`claims.md` Claim 16 과 일치한다.

- **시각 자료·범위·교차 참조.** `block-table-indexing` mermaid 마커와

## Problems

   받고(`src/kernels.cu:347`)"는 실제 시그니처
   `(int *gpu_last_tokens, int num_tokens, __nv_bfloat16 *output, __nv_bfloat16

   대비 의도는 그대로이고 사실 오류는 아니며, ko-05 리뷰 Problem 1 과 같은 성격의
   표기 정밀도다.
2. **블록 읽기 인용 구간의 경계.** "논리 블록 → 물리 블록 → 바이트 주소" 절의

   포함한다. 내용은 정확하고 절 서두("몇 블록을 읽을지 세고…")가 470-481 을
   아우르므로 실질 문제는 없다.
3. **(정보용) online softmax 인용 509-519.** `509` 는 `// online softmax` 주석
   줄이라 510 부터 시작하는 `claims.md` Claim 17 과 차이가 무해하다. ko-05 리뷰
   Problem 4 와 같은 성격.
4. **(정보용) `src/kernels.cu` 의 `KV_CACHE_SIZE_BYTES`·`NUM_BLOCKS` 부재.**
   "같은 상수(`kernels.cu:16-19`)가 다시 정의되어 있다"에서 커널 쪽은
   `BLOCK_SIZE`·`V_OFFSET`·`BLOCK_BYTES`·`MAX_BLOCKS_PER_SEQ` 넷만 다시 정의하고
   캐시 크기·블록 수 상수는 `main.cpp` 전용이다. 문맥상 "같은 상수"가 넷을
   가리키므로 사실과 어긋나지 않지만, 열거가 더 명시적이면 좋다.

# ko-09 리뷰 — online softmax CUDA kernel

기준 커밋 `1896ff5c37a241050dbcd9527caf9dc1d3087a61`의 실제 소스
(`src/kernels.cu`, `src/main.cpp`, `src/cuda_to_hip.h`)와 근거 문서
(`evidence/claims.md`, `evidence/trace.md`, `evidence/recon.md`, `briefs.md`,
`series.yaml`, `guide.md`)를 대조해 모든 기술 주장을 검증했다.

## Decision

**REVISE** — 모든 기술 주장과 소스·근거 인용은 전부 정확하다. 잘못된 사실이나
근거 없는 성능 주장은 없다. 다만 **briefs.md:204와의 범위 충돌** 하나가 있어
수정이 필요하다. 초안이 "prefill softmax 커널 내부 상세를 배제한 범위와도
맞는다"고 단순히 선언하는 것(`:141-142`)은 brief의 실제 문구("4·5장 문맥에서만
언급한다")와 어긋난다. 이 한 건만 고치면 된다.

## Verified claims

아래는 초안의 주장을 실제 소스 줄과 근거 문서 줄에 직접 대조해 검증한 결과다.

- **Claim 8 주 소유 (online softmax 갱신)** — `current_max`/`acc`/`d` 초기값
  (`kernels.cu:474-476`: `-INFINITY`, `0.0f`, `0.0f`), `d` 주석 "denominator,
  same name as in paper above"(`:476`), 토큰 루프(`:478-482`), 갱신 규칙
  (`:510-519`), 출력 `acc/d`(`:522`). 초안의 갱신 유사코드(`:63-74`)는 소스와
  줄·식이 모두 일치한다. `correction_factor = expf(current_max - new_max)`
  (`:515`)로 이전 누적을 재환산하는 설명도 수학적으로 정확하다.
- **Claim 8 참조 (warp 트리 합)** — `dot_products[2]` 공유 배열(`:463`), Q의
  1차원 담당(`:469`, 식 `active_slot*2048 + q_head_id*64 + thread_id` 일치),
  `k`/`qk`(`:484-486`), `__shfl_down_sync` 오프셋 16·8·4·2·1(`:489-493`),
  thread 0/32 → `dot_products[0]/[1]`(`:494-501`), `__syncthreads`(`:502`,
  `:507`), thread 0의 합·`SQRT_HEAD_DIM` 나눗셈(`:503-506`), 모든 스레드의
  `dot_product` 읽기(`:508`). 전부 소스와 일치.
- **커널 정의와 launch** — `pagedAttentionKernel`(`:461-523`), 래퍼 그리드
  `(num_active_slots, NUM_Q_HEADS)`·블록 `HEAD_DIM=64`(`:525-527`),
  `HEAD_DIM=64`(`:11`), `SQRT_HEAD_DIM=8`(`:12`). `HEAD_DIM=64`가 정확히 두
  개의 완전한 warp을 만든다는 한계 서술(`:182-185`)도 소스에서 확인된다.
- **스케일 정합** — `attn_alpha = 1.0f / 8.0f`(`main.cpp:649`)와 prefill 스코어
  GEMM 주석 `Q_head * K_head^T / sqrt(64)`(`main.cpp:298`)이 1/sqrt(64)와
  일치한다는 주장 정확.
- **마스크 정의** — `WARP_FULL_MASK`: HIP 64비트
  `0xffffffffffffffffULL`(`cuda_to_hip.h:50`), CUDA 32비트
  `0xffffffff`(`:59`). 실제로 각 경로에서 그렇게 정의된다.
- **prefill 대비 문맥** — prefill `softmaxKernel`이 global `input`
  (`prefill_attn_scores`, `main.cpp:331`에서 실제로 전달)을 대상으로 shared
  `m[1024]`/`d[1024]`(`kernels.cu:259-260`) 환원 상태를 쓰고 병렬 트리 환원
  후 제자리 덮어쓰며(`:270-289`), `:281`이 재스케일
  `d_new = d_a*expf(m_a-m_new) + d_b*expf(m_b-m_new)`인 것 모두 소스에서
  확인된다. "prefill도 온라인 softmax다"라는 분류는
  `evidence/trace.md:112-113`이 지지한다.
- **호출 지점 체인** — decode KV 산포(`main.cpp:851-873`) → `block_table_gpu`

  실제로 다뤘음을 확인했다.
- **마스킹 방식** — `num_blocks`(`kernels.cu:471`)와 `tokens_in_block`(`:481-482`)
  계산이 소스와 일치하고, "누적 K만 읽음 = causal 마스킹"은
  `evidence/claims.md:88`이 그대로 지지한다.
- **검증 경로·한계** — 단일 커널 테스트(`evidence/recon.md:12`), 저장소 미실행

  code(`kernels.cu:408-458`; `evidence/trace.md:216-219`) 모두 근거와 일치한다.

## Problems

1. **범위 충돌 (경미): prefill softmax 커널 내부 상세가 briefs.md:204와
   어긋난다.** `briefs.md:204`는 이 장(9장)의 배제로 "prefill의 별도 `softmax`
   커널은 **4·5장 문맥에서만** 언급한다"고 한정한다. 그런데 초안의 대비 표
   (`:136-139`)는 `softmaxKernel`의 내부 상세(shared `m[1024]`/`d[1024]`,
   `:259-260`; 병렬 트리 환원 후 제자리 덮어씀, `:270-289`)를 기술한다. 또
   초안은 "그 자체의 커널 상세를 확장하지 않는다"(`:31-33`)고 하면서 상세 행을
   싣는 자기모순이 있고, "이 대비는 briefs.md가 이 장에서 prefill 커널 내부
   상세를 배제한 범위와도 맞는다"(`:141-142`)는 brief의 실제 문구를
   "대비용이면 허용"으로 완화해 요약한 것이라 인용으로도 부정확하다. 표 내용
   자체는 사실 정확하므로 오류가 아니라 범위/자기일관성 문제다.
2. **(선택, 경미) 근거 인용 정밀도** — "prefill도 `:281`의 재스케일을 쓰는
   온라인 softmax다(`evidence/trace.md:112-113`)"(`:133-134`)에서
   `trace.md:112-113`은 "온라인 softmax" 분류만 지지하고 `:281` 세부는 지지하지
   않는다. `:281`은 소스로 직접 검증되므로 사실 오류는 아니고, 각주급 인용
   정밀도 문제다.

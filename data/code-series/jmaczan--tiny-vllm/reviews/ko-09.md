# Review: ko-09.md (online softmax CUDA kernel)

## Decision

REVISE

## Verified claims

고정 커밋 `1896ff5c37a241050dbcd9527caf9dc1d3087a61`의 `src/kernels.cu`,
`src/main.cpp`, `tests/test_softmax.cu`와 `evidence/claims.md`, `evidence/trace.md`,
`evidence/recon.md`, `briefs.md`, `guide.md`, `series.yaml`를 대조해 모든 기술
주장과 인용을 확인했다.

- **Claim 8 (주 소유)** — `current_max`/`d`/`acc` 갱신과 `acc/d` 출력이 소스와 정확히
  일치. 커널 본문의 `:509-519`는 `new_max` 계산(`:510-514`) → `correction_factor =
  expf(current_max - new_max)`(`:515`) → `d`/`acc` 재스케일·누적(`:518-519`)이고,
  `:522`는 `output = acc / d`. 갱신 규칙(새 최댓값 등장 시 `exp(current_max - m_new)`
  배 재스케일)이 claims.md:82와 소스에 그대로 존재.
- **Claim 8 (참조)** — 각 스레드가 Q의 1차원을 담당(`:469` q 읽기), warp 내
  `__shfl_down_sync` 5단 트리 합(`:489-493`, 오프셋 16/8/4/2/1 = log2(32)),
  `dot_products[2]` 크기 2 shared 배열로 두 warp 결합(`:463`, `:494-507`)이 소스와
  일치.
- **실행 구조** — 그리드 `(num_active_slots, NUM_Q_HEADS)`, 블록 `HEAD_DIM=64` 래퍼
  (`:525-527`), decode 호출 지점(`src/main.cpp:878`)이 일치. `gpu_active_slots` 매핑
  (`:464-465`) 후 블록 테이블 행 조회(`:480`), 물리 블록·토큰 순회와 K·V 읽기
  (`:482-520`, K `:484`·V `:485`)가 소스와 일치. `kv_head_idx = q_head_id /
  GQA_Q_TO_K_RATIO`(`:468`)와 GQA 상수(`src/main.cpp:20-24`) 일치.
- **마스킹 서술** — "이미 쓴 KV만 읽어 미래 토큰 스코어가 계산되지 않음"이 claims.md:88
  및 누적 토큰만 순회하는 `:478-482` 구조와 일치.
- **prefill 대조** — `causalMask`(`:224-237`)와 `softmax`(`:257-290`) 커널 범위가 소스와
  일치. prefill softmax가 단일 트리 결합으로 최댓값+합을 계산한다는 대조는
  trace.md:112-113 및 `:270-287`의 m/d 공동 환원과 일치. decode가 `softmaxDecode`
  대신 `pagedAttentionKernel` 내부 온라인 갱신을 쓴다는 점은 trace.md:216-219와 일치.
- **도입부 8장 요약** — KV 산포(`:851-873`) → `block_table_gpu` 재동기화(`:876`) →
  `pagedAttention`(`:878`) 순서가 main.cpp와 claims.md:107-109에 일치.
- **한계·범위** — 커널 테스트가 `tests/test_softmax.cu` 하나뿐(claims.md:24,
  recon.md:12)이고, `test_softmax.cu`가 독립 fused softmax 커널을 검증하며
  `pagedAttentionKernel`의 dot product·온라인 softmax 수치를 검증하지 않는다는
  서술이 정확(테스트 소스는 pagedAttention 커널을 참조하지 않음). "성능 주장 없음"은
  guide.md:7-9 범위 규칙과 일치. 9장 대상 파일 `src/kernels.cu`,
  `tests/test_softmax.cu`(`series.yaml:29-30`) 및 `briefs.md:203` 배제 규칙과 일치.

## Problems

1. **도식 라벨의 줄 인용 오류** — 다이어그램에서 "각 스레드 = Q의 1차원 (:489)"로
   인용했으나 `:489`는 첫 `__shfl_down_sync`이고, 스레드당 1차원 담당은 `:469`의
   `q_proj[... + q_head_id * HEAD_DIM + thread_id]` 읽기이다. 실질 내용은 정확하나
   줄 인용이 틀렸다.
2. **claims.md 인용 불일치** — 본문이 갱신 규칙의 근거로 `evidence/claims.md:83-85`를
   달았는데, 해당 범위는 Confidence/Evidence 머리말이다. 온라인 softmax의 실제 근거
   줄은 claims.md:86(`:509-519`, `:522`)이다. 소유 주장 표에서는 `claims.md:82-88`로
   올바르게 달아 둔 것과 어긋난다.
3. **범위 경계와 실제 서술의 내적 모순** — 도입부(`:31-32`)와 "이 장에서 다루지 않는
   것"(`:153`)은 "커널의 그리드 배치와 블록 테이블 순회·KV 읽기 전체는 10장으로
   넘긴다"고 선언하지만, 본문 `:89-101`과 도식 `:118-130`은 정작 그리드
   `(num_active_slots, NUM_Q_HEADS)`·블록 `HEAD_DIM=64`, `gpu_active_slots` 매핑,
   블록 테이블 행 조회(`:480`), 물리 블록·KV 읽기(`:482-520`)를 상세히 서술한다.
   "다루지 않는다"고 한 것을 실제로 다뤄 배제 목록이 내용과 모순된다.

## Required fixes

1. 도식 라벨 인용 수정: "각 스레드 = Q의 1차원 (:489)" → `(:469)`.
2. 본문 갱신 규칙의 근거 인용 수정: `evidence/claims.md:83-85` → `evidence/claims.md:86`
   (또는 소유 주장 표와 동일하게 `:82-88`로 통일).
3. 범위 모순 해소: `:31-32`와 `:153`의 배제 문구를 실제 서술과 맞추라. 온라인 softmax를
   설명하기 위해 그리드·블록 테이블 순회·KV 읽기를 맥락으로 쓴 부분이 있으므로, 배제
   문구를 "그리드·순회·KV 읽기의 전체 구조와 상세는 10장"으로 완화하거나, 반대로
   `:89-101`·`:118-130`의 중복 서술을 축소해 어느 한쪽으로 통일해야 한다.

기술 주장 자체는 전부 소스·claims.md와 일치하고 성능 주장이나 근거 없는 수치는 없다.
위 세 항목을 고치면 게재 가능하다.

# ko-04 검토 — cuBLAS 전치 트릭

검토 대상: `articles/ko-04.md`(4편 `cublas-and-layout`). 근거: `guide.md`,
`series.yaml`, `evidence/claims.md`, `evidence/trace.md`, `evidence/recon.md`,
그리고 줄 단위 소스 대조 사실을 기록한 이전 검토 산출물 `reviews/en-04.md`.
`src/main.cpp`·`src/kernels.cu` 본문은 첨부에 없으므로, 줄 번호 대조는
`claims.md`/`trace.md` 의 범위 인용과 `en-04.md` 가 밝힌 고정 revision
`e25bf19` 대조 결과를 교차로 사용했다.

## Decision

**PASS**

핵심 기술 주장(전치 트릭의 대수, 여덟 개 가중치 투영 + 어텐션 점수 + 점수×V
열 개의 cuBLAS 호출, alpha·beta 전부 0.0 과 잔차 커널 분담)이 첨부 근거와
전부 일치한다. 첨부만으로는 확인이 어려운 세부(상수 줄 위치, alpha·beta 열 개
쌍의 정확한 줄 번호, `*_status` 미검사 전제, decode 의 `n = num_active_slots`)
는 `en-04.md` 의 소스 대조 결과가 그대로 뒷받침한다. 특히 `series.yaml` 의
원래 요구 주장 중 코드로 뒷받침되지 않는 "alpha·beta 가 잔차 누적을 별도
커널 없이 처리한다"는 항목을, 초안은 데이터로 반박하는 방식으로 올바르게
처리했다(`claims.md` Claim 9 의 한계와 일치). 성능 주장은 전혀 없고, 아래
Problems 는 모두 비차단 관찰이다.

## Verified claims

1. **레이아웃 불일치와 트릭 골격**(5, 9, 11, 26줄): 행 우선 데이터를 열 우선을
   가정하는 cuBLAS 에 전치 플래그·ld 만으로 넘기는 해석은 `claims.md` Claim 9
   와 일치한다. Q 소스 주석(`main.cpp:168-176`)의 인용과
   `C = A·B == C^T = B^T·A^T` 항등식 활용 서술이 정확하다.
2. **Q 투영의 대수**(56-62줄): `op(A)=w_q`(`CUBLAS_OP_T`),
   `op(B)=rms_norms^T`(`CUBLAS_OP_N`), `m=2048, n=prompt_len, k=2048`.
   cuBLAS 가 쓰는 열 우선 C = `w_q·rms_norms^T` 를 행 우선으로 읽으면
   `(w_q·rms_norms^T)^T = rms_norms·w_q^T = Q` 라는 유도가 수학적으로 맞다.
   `lda=ldb=ldc=2048`(187/190/194)은 `claims.md:175-176` 의 `184-194` 범위와
   일치한다.
3. **K/V, O, SwiGLU, 로짓의 공통 골격**(68-110줄): K(`201-219`, m·ldc=`KV_DIM`
   204/217), V(`222-240`), O(`378-396`, "same as Q projection" 주석 376,
   m=ldc=2048), gate(`414-432`), up(`435-453`), down(`461-489`, 주석
   461-469, lda=ldb=8192, m=ldc=2048), 로짓(`509-527`, m·ldc=`VOCAB_SIZE`
   512/525, 정정 주석 496-501). 모든 범위가 `trace.md`·`claims.md` 와 일치하고,
   down·로짓 주석의 직접 인용 텍스트는 `en-04.md` 가 고정 revision 에서
   확인했다.
4. **어텐션 점수**(114-149줄): `main.cpp:301-327`, `k_head_idx = i/GQA_Q_TO_K_RATIO`(303),
   `m=n=prompt_len, k=64`(311-313), `lda=KV_DIM`(317), `ldb=EMBEDDING_LENGTH`(320),
   `ldc=prompt_len`(324), `attn_alpha=1/8`(649, = 1/√64). "열 우선
   C = `k_head·q_head^T` → 행 우선 `q_head·k_head^T`" 유도가 맞다.
   `claims.md` Claim 8 과 일치한다.
5. **점수×V 예외 호출**(153-182줄): 유일한 `OP_N`/`OP_N` 호출, `m=64,
   n=k=prompt_len`(355-357), `lda=KV_DIM`(361), `ldb=prompt_len`(364),
   `ldc=EMBEDDING_LENGTH`(368), 출력 `attn_scores_v + i·HEAD_DIM`(350),
   유일한 `ldc≠m`(368), 그 결과가 O 투영 입력(343, 388). "열 우선
   C = `V^T·S^T` → 행 우선 `S·V`" 유도와 헤드 32개가 `[i*64, i*64+64)` 구간으로
   쌓여 (prompt_len, 2048) 을 채운다는 해석이 모두 맞다. `trace.md` 의
   `343-371` 범위와 일치한다.
6. **alpha·beta 와 잔차**(186-204줄): 열 개 쌍의 줄 번호(`631-679`)와 beta
   전부 0.0, 유일한 비-1.0 alpha = `1/8`(649), 잔차는 `residualAdd` 커널(399,
   492)이 담당한다는 서술은 `claims.md` Claim 9 의 한계 기록과 정확히 일치한다.
7. **시각 자료**(210-217줄): mermaid 다이어그램 5개 노드(A-E)와 `main.cpp`
   앵커(168-169, 169, 170, 179, 180, 171-176)가 첨부 범위와 일치하며,
   `series.yaml` 의 `column-row-major-trick`(mermaid,
   required_claims `[column-row-major-trick]`)을 충족한다. guide 의
   "각 시각 자료가 답할 질문과 근거 경로를 가진다"는 조건도 만족한다.
8. **범위·한계 서술**: decode 대비는 5편으로, GQA 개념은 3편으로 위임해 guide
   의 편 분할·용어 소유 규칙을 따른다. "이 편은 `src/main.cpp` 만 다룬다"는
   `series.yaml` 의 `code_scopes` 와 일치한다. 빌드·실행 미검증, `*_status`
   미검사 전제, 컴파일 타임 상수 의존(`16-25`) 등 한계 서술은 결정 003(정적
   대체 검증)과 일치하고, 측정값을 암시하는 문장은 없다.

## Problems

비차단 관찰이다. guide 의 통과 조건(모든 기술 주장의 permalink 인용, 최소
근거 code 3 충족, runtime 0, required_claims 충족)을 어기지 않는다.

1. **`GQA_ATTN_SCORES_TO_V_RATIO` 식별자**(178줄): 이 상수 이름은 첨부 근거
   (`claims.md`·`trace.md`·`guide.md`) 어디에도 없다. 첨부에 존재하는 GQA
   식별자는 `GQA_Q_TO_K_RATIO` 하나뿐이다. "(3편)"으로 위임된 문맥이라 위험은
   낮지만, 게시 전에 고정 revision 에서 이름을 확인하거나 3편의 검증된 인용으로
   치환하는 것이 안전하다.
2. **상수 줄 번호의 근거 문서 불일치**(9, 231줄): 초안은 `EMBEDDING_LENGTH` 를
   `src/main.cpp:16`, 상수 블록을 `16-25` 로 인용하는데, `claims.md` Claim
   8(`19-24`)·Claim 4(`19-31`)는 다른 범위를 든다. `en-04.md` 가 "16=
   EMBEDDING_LENGTH, 18=KV_DIM, 19=HEAD_DIM"을 소스에서 확인했으므로 초안이
   정확하고, `claims.md` 쪽 범위는 각기 다른 상수 하위 집합(어텐션·버퍼 크기)을
   가리키는 것으로 보인다. 초안 수정은 불필요하나, 근거 문서의 정합성을 위해
   `claims.md` 의 범위 주석을 초안·`en-04.md` 와 맞추는 것을 권한다.
3. **"더 읽을거리"의 Paged Out! 링크**(226줄): `https://pagedout.institute/` 는
   매거진 홈이며 "The cuBLAS transposition trick" #9 글의 permalink 가 아니다.
   소스 인용 규칙과 별개로, 해당 글 바로가기를 걸면 독자 편의가 올라간다.
4. **(정보용) 블록 인용 문구의 재현 범위**: 주석·코드 블록의 정확한 문구는
   첨부에 원문이 없어 1:1 대조는 불가능하다. 단 모든 블록의 줄 범위가
   `trace.md`/`claims.md`/`en-04.md` 와 일치하므로 실질 오류 위험은 낮다.

# ko-04 리뷰 — cuBLAS 행렬곱과 열-행 우선 전치 트릭

고정 revision `e25bf1994efa90bc98b721ba7c527402f86fbeaf` 의 체크아웃 트리
(`src/main.cpp`)와 첨부 증거(`guide.md`, `series.yaml`, `evidence/claims.md`,
`evidence/trace.md`, `evidence/recon.md`)를 기준으로 `articles/ko-04.md` 의 모든
기술 주장·인용·범위·소유권·산술·성능 서술을 대조했다. 특히 10개 cuBLAS 호출 각각의
`opA`/`opB`·`m`·`n`·`k`·`lda`·`ldb`·`ldc` 를 소스 원문과 하나씩 대조했고, 전치
트릭의 수식 유도(`op(A)`, `op(B)` 기준)를 독립적으로 재계산했다.

## Decision

**PASS**

행 우선 데이터와 열 우선 cuBLAS 의 불일치, 전치 항등식의 수식 유도, 여덟 가중치
투영의 공통 골격(`CUBLAS_OP_T`/`CUBLAS_OP_N`, `n = prompt_len`, `ldc = m`),
Q/K/V·O·SwiGLU·로짓 각 호출의 인자, 점수×V 호출이 `ldc ≠ m` 인 예외의 인과, alpha
중 `1/8` 하나를 뺀 1.0·beta 전부 0.0 그리고 잔차가 별도 커널 `residualAdd` 라는
기각, `column-row-major-trick` 시각 자료까지 모든 기술 주장이 실제 소스와 첨부
증거에 정확히 일치한다. 최소 근거 `code 3 / tests 0 / runtime 0` 을 충족하고,
측정값으로 읽힐 성능 수치는 없다. 수정을 요구하는 오류는 찾지 못했다. 아래 2건은
비차단 정밀도 관찰이며 수정 선택 사항이다.

  재정의하지 않고 링크만 한다.
- **행 우선 데이터와 소스 주석 인용.** "모든 활성과 가중치는 행 우선"이 소스

  블록 — `src/main.cpp:168-169`("Q = inputs * wq^T; ... perceives my matrices as
  transposed")과 `src/main.cpp:170`("C = A * B == C^T = B^T * A^T") — 이 원문과
  문자 단위로 동일하다. "Q^T 를 다시 Q 로 되돌릴 필요가 없다"는

- **전치 트릭 수식 유도.** `op(A)`/`op(B)` 기준의 유도가 독립 재계산과 일치한다.
  행 우선 (2048, 2048) `w_q` 를 `lda=2048` 로 열 우선 읽으면 `w_q^T`, `OP_T` 로
  되돌려 `op(A) = w_q`. 행 우선 (prompt_len, 2048) `rms_norms` 를 열 우선 읽으면
  `rms_norms^T`, `OP_N` 이므로 `op(B) = rms_norms^T`. 열 우선 C = `w_q ·
  rms_norms^T`, 행 우선으로 읽으면 `(w_q·rms_norms^T)^T = rms_norms·w_q^T = Q`.
  `(m, k) = (2048, 2048)`, `(k, n) = (2048, prompt_len)` 도 맞는다. 소스 주석의

## Problems

수정이 필요한 오류는 없다. 아래는 정밀도·표현 관찰이다.

- **O1 (선택, 인용 정밀도).** 초안 28-30행은 Q 가중치의 `(out=2048, in=2048)` 형상과
  행 간격 2048 을 `src/main.cpp:16, 185` 로 인용한다. 그런데 (out, in) 표기 규약은
  소스 주석이 K/V 에만 명시한다(`src/main.cpp:198-199`, "weights = (KV_DIM,
  EMBEDDING_LENGTH)"). Q 의 형상은 `m = k = lda = 2048`(`src/main.cpp:181`, `183`,
  `187`)과 모델 사양으로부터 따라나오는 추론이라 주장 자체는 정확하고 (out, in)이든
  (in, out)이든 사각 행렬이라 행 간격 2048 은 변하지 않는다. `181`/`183`/`187` 을
  함께 인용하면 추론 근거가 더 또렷해진다.
- **O2 (선택, 정밀도).** 초안 43-45행 "열 우선 행렬에서 leading dimension `ld` 는
  ... 곧 행 수다"는 엄밀히 `ld ≥ 행 수` 가 성립한다. 여기 다루는 모든 버퍼가
  padding 없는 조밀 배열이라 "행 수"로 읽어도 사실과 어긋나지 않는다. "패딩이
  없으면 행 수와 같다"로 다듬으면 정의상 더 정확하다.

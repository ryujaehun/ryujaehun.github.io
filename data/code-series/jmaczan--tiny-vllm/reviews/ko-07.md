기술 서사의 뼈대 — 슬롯·큐 두 저장소, `is_slot_free` 점유, 초기 prefill 채움,

`src/main.cpp` 와 첨부 근거(`claims.md`, `trace.md`, `guide.md`, `briefs.md`,

`hidden_state` 상태 변경 행이다. (2) "이 세 디바이스 배열은 `pagedAttentionKernel`
의 입력이 된다"는 서술은 `gpu_last_tokens` 를 잘못 포함한다. (3) `src/main.cpp:743`
TODO 주석의 내용을 `BATCH_SIZE` 임시값으로 잘못 요약했다. 세 곳 모두 수정이
필요하다. 미지원 성능 주장은 없다.

## Problems

1. **`gpu_last_tokens` 근거로 인용한 `trace.md:181` 이 다른 행을 가리킨다.**
   초안 `articles/ko-07.md:122-124` 는 "`gpu_last_tokens` 는 decode 전용
   버퍼로, 슬롯별 마지막 토큰을 담는다 (`src/main.cpp:684-685`;
   `trace.md:181`)"라고 쓴다. 그러나 `trace.md:181` 은 상태 변경 표의
   `hidden_state` 행이다. `gpu_last_tokens` 를 뒷받침하는 줄은
   `trace.md:73`("decode 전용: `gpu_last_tokens`(`684-685`)")과
   `trace.md:129`(H2D `gpu_last_tokens`(`749`))다. 상태 변경 표에는
   `gpu_last_tokens` 행이 아예 없다.
2. **"이 세 디바이스 배열은 `pagedAttentionKernel` 의 입력이 된다"가 사실과
   어긋난다.** 초안 `articles/ko-07.md:132-134` 는 `gpu_last_tokens`·
   `gpu_active_slots`·`gpu_seq_lens` 세 배열을 `pagedAttentionKernel` 의
   입력이라고 묶는다. 그러나 Claim 16(`claims.md:303-306`)과 호출부
   `src/main.cpp:878`(`pagedAttention(layer, num_active_slots, q_proj, kv_cache,
   block_table_gpu, gpu_seq_lens, gpu_active_slots, buf_2048_1)`)에 따르면 이
   커널이 받는 상태는 `kv_cache`·`block_table_gpu`·`gpu_seq_lens`·
   `gpu_active_slots` 뿐이다. `gpu_last_tokens` 는 `src/main.cpp:759`
   (`embeddingGatherDecode(gpu_last_tokens, ...)`)로 들어가며
   `pagedAttentionKernel` 의 입력이 아니다.
3. **`src/main.cpp:743` TODO 주석의 내용을 잘못 요약했다.** 초안
   `articles/ko-07.md:109-110` 은 "`BATCH_SIZE` 와 같은 임시값임을 밝히는 TODO
   주석도 이 break 지점에 있다"라고 쓴다. 실제 743행 주석은 "continue will make
   sense when I will finally write to queue, for now it has predefined size so
   break instead"로, break/continue 선택과 큐의 고정 크기를 말할 뿐
   `BATCH_SIZE` 를 언급하지 않는다. `BATCH_SIZE` 의 "not even close to being
   good" 주석은 29행에 따로 있다.
4. (경미) **`guide.md:199` 인용이 기술 주장을 뒷받침하지 않는다.** 초안
   `articles/ko-07.md:33-34` 의 "슬롯마다 KV 블록을 가리키는 테이블 행이
   하나씩 있다(`guide.md:199`)"에서 `guide.md:199` 는 block table·paged
   attention 의 6편 소유권만 밝힌다. "슬롯마다" 라는 사실은
   `src/main.cpp:579` 와 인덱싱 식(`slot * N_LAYERS * MAX_BLOCKS_PER_SEQ + ...`)이
   근거다. 또한 실제로는 슬롯마다 `N_LAYERS × MAX_BLOCKS_PER_SEQ` 개 항목이지
   "행이 하나씩"은 아니다.
5. (경미) **초기 채움 조건 요약이 부정확하다.** 초안
   `articles/ko-07.md:73-74` 는 조건을 "빈 슬롯이 남아 있고 큐에 프롬프트가 남아
   있는 동안"이라고 푼다. 실제 조건(`src/main.cpp:695`)은
   `slot < is_slot_free.size() && !queue.empty()` 이고, 비어 있지 않은 슬롯은
   루프 안 `continue`(`697-700`)로 건너뛴다. 초기 상태에서는 결과가 같지만
   조건식 자체와는 다르다.
